# ADR-0066: IdP で入っていれば、ログイン画面でボタンを押させない

- 日付: 2026-10-22
- 状態: 承認

## 文脈

IdP（assay）で既に入っていても、アプリのログイン画面は「〇〇でログイン」を押させていた。
押せば画面を出さずに戻ってくるので、押す手間だけが残っている。全アプリ共通の形は
nolumiatask #644 で決めた（このテンプレートから作ったアプリへ配るのは #645）。

## 決定

1. ログイン画面は、条件がそろえば**入口を描く前に** `GET /api/auth/sso/login?prompt=none` へ
   画面遷移する。サーバーは認可要求に `prompt=none` を付け、往復状態（Cookie）に「試した往復」と書く。
   iframe は使わない（上の階の画面遷移だけ）。
2. IdP で入っていれば code が返り、ふつうの SSO と同じ道（引き換え券 → `/login/sso`）で入る。
   行き先（`redirect_to`。ADR-0055）もそのまま使う。
3. 試した往復の戻りが `login_required`・`consent_required`・`interaction_required`・
   `account_selection_required` なら、**失敗として記録せず**、`?sso_silent=declined&redirect_to=…` で
   ログイン画面へ戻す。画面はエラーを出さずにふつうの入口を出す。
4. 試さないとき（`frontend/src/services/silentSso.ts`）:
   - サインアウトした後（`localStorage` の印。ほかのタブでも試さない）
   - このタブで一度試した後（`sessionStorage` の印）
   - URL に `redirect_to` 以外のもの（`sso_error`・`signed_out`・`sso_silent` など）が付いているとき
   - SSO が無効なとき・印を書けないブラウザ
   どちらの印も、どの入口でも入れたら消す（次に期限が切れたときはまた試す）。
5. IdP では通ったがアプリ側で断られたとき（口座が無い・止められている等）は、今までどおり
   `?sso_error=<コード>` で出す。

## 理由

- **サーバーの往復状態に「試した」を書く**のは、ボタンで始めた往復の `login_required` まで
  黙って飲み込まないため。クエリの印だけで決めると、URL を書き換えて失敗を隠せる。
- **サインアウトの印を `localStorage` に置く**のは、サインアウトが既定で IdP の SSO を切らない
  （ADR-0033）から。印が無いと、ログイン画面を開いた瞬間に入り直してしまう。タブを開き直しても
  効かせたいので `sessionStorage` にはしない。
- **試した印を `sessionStorage` に置く**のは、ループ止めはそのタブだけに効けば足りるから。
  加えて戻りの URL にも `sso_silent` を付けるので、印が消えても行き来は 1 往復で止まる。
- iframe で裏から確かめる形は採らない。IdP の画面を枠に入れると第三者 Cookie の扱いに左右され、
  CSP の `frame-ancestors` も開けることになる。

## 影響

- ログイン画面を開くと、条件がそろうときは一瞬 IdP へ出て戻る（画面には「読み込んでいます」だけが出る）。
- 監査ログの「SSO ログイン失敗」には、試して断られた分は積まない（アプリログに
  `sso_silent_login_declined` が出る）。
- このテンプレートから作ったアプリへは、各リポジトリの入口を読み直して手で当てる（#645）。
