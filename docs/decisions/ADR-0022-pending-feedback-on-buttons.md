# ADR-0022: サーバーへ問い合わせる操作は、押した直後にスピナーで実行中を示す

- 日付: 2026-08-03
- 状態: 承認

## 文脈

サーバーへ問い合わせる操作は、応答が返って画面を描き直すまで見た目が変わらない。
押せたのかどうかが分からないため、利用者は同じボタンを続けて押す。回線が遅いほど
その間隔は長くなり、二重登録・二重削除の元になる。

各画面が `busy` の `useState` を自前で足す形も取れるが、実際には足した画面と
足していない画面が混ざっていた（例: パスキー登録だけがラベルを「読み込み中...」へ
差し替え、他の送信ボタンは無反応）。新しい画面を書くたびに書き忘れが増える。

一覧の中の操作にも同じ問題がある。チェックボックスの `checked` はサーバーの応答で
決まるため、押しても取得し直すまで表示が変わらない。

## 決定

サーバーへ問い合わせるボタンは `components/ActionButton.tsx` を使い、実行中は
スピナーを出して押せなくする。実行中かどうかは `hooks/usePendingAction.ts`
（単発の操作）と `hooks/usePendingRows.ts`（一覧の行ごとの操作）が持つ。
ラベルは差し替えず、スピナーを前に足すだけにする。

## 理由

- **目印を出す責務を部品側へ寄せた。** 画面ごとに `busy` を書くのをやめ、
  「`ActionButton` に `pending` を渡す」1 つの形へ揃える。書き忘れは
  「素の `<button>` のまま」として差分に現れる。
- **二重送信の防止を同じ場所に置いた。** `disabled` は次の描画まで効かないので、
  同じフレームで続けて押された 2 つ目は止められない。フックが `ref` で判定して
  実行中の再呼び出しを無視する。目印と防止を別々に実装すると片方だけ入る。
- **ラベルを差し替えない。** 「保存」→「読み込み中...」と入れ替えると幅が動き、
  押した位置がずれる。またラベルが消えると、何を実行中なのか分からなくなる。
- **文言も残す。** 回る印は目でしか分からないため、`aria-busy` に加えて
  読み上げ用の文言（`common.processing`）を視覚外に置く。
- 代替として「画面全体を覆うオーバーレイ」も検討したが、押した場所と目印が離れ、
  一覧の行ごとの操作を表現できないため採らなかった。

## 影響

- サーバーへ問い合わせる新しいボタンは `ActionButton` で書く。素の `<button>` は
  画面内で完結する操作（表示の切り替え・入力の消去・メニューの開閉）に限る。
- 検索・ページ送りのように「押すと表の中身が入れ替わる」操作も対象。ログ画面は
  `hooks/useLogSearch.ts` が取得中かどうかを返す。
- 目印の見た目は `src/index.css` の `.spinner` が唯一の出所。動きを減らす設定
  （`prefers-reduced-motion`）では止めずに遅くする（実行中を伝える唯一の目印のため）。
