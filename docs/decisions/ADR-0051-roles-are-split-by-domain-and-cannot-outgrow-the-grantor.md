# ADR-0051: ロールは系統で分け、権限は自分の範囲でしか動かせない

- 日付: 2026-10-05
- 状態: 承認（全権限のロールの名前 `admin` は ADR-0052 で `owner` に置き換え）

## 文脈

雛形のロールは `admin`（全権限）/ `manager` / `member` / `guest` の 4 つで、強さの
1 列だった。「管理する人」がシステムの設定を触る人なのか、利用者を世話する人なのか、
中身を扱う人なのかが分かれておらず、派生アプリは `admin` を配るか自前で組むしか
なかった。

また、scope の検査（`require_permission`）は「その画面を使えるか」までしか見ない。
そのため次のことができた。

- `user:manage` だけを持つ人が、自分や他人に `admin` を付ける（昇格）
- `user:manage` だけを持つ人が、`admin` のパスワードを書き換えて乗っ取る
- 管理者が自分のロールを外す・自分を止める・自分を消す（Progress の T4。誰も管理画面に
  入れなくなる）
- 最後の `admin` ロールから `role:manage` を外す・ロールごと消す

## 決定

1. ロールの雛形を**扱うものの系統**で分ける。`system-admin`（システム）・
   `user-admin`（人）・`auditor`（監査。読むだけ）を足し、`manager` / `member` /
   `guest` はコンテンツの系統とする。`admin` は全権限を持つ持ち主として残す。
   系統をまたぐロールは雛形に置かない。
2. 管理 API で権限を動かす操作に、scope とは別の関門を掛ける
   （`presentation/fastapi/routers/admin/authority_guard.py`）。
   - **自分が持っていない権限は、配ることも取り上げることもできない**（ロールの付け外し・
     ロールの中身の変更。付けたものと外したものの両方を見る）
   - **自分より多くの権限を持つ利用者には触れない**（パスワード・名前・有効状態・削除）
   - **自分のロール・有効状態・存在は変えられない**（名前とパスワードは変えてよい）
   - **「管理の要」（`user:manage` と `role:manage` の両方）を持つ有効な利用者を 0 人に
     する変更は 409 で戻す**
3. 比べる「自分の権限」は、いま有効な scope（アクティブロールで絞った後。ADR-0017）。

## 理由

- **系統で分ける**: システム・人・中身は、触れてよい人も、誤ったときの被害も違う。
  1 列の強さでは「設定は触るが中身は見ない」「中身は全部扱うが人は配らない」が
  表せない。監査を読むだけのロールは、変える人と確かめる人を分ける（職務の分離）ために要る。
- **`manager` の名前を変えない**: 既存の派生アプリと発行済みのトークンがロール名を
  持っている。系統の説明はマスタデータの注釈で足りる。
- **配れるのは自分の範囲まで**（Kubernetes の RBAC が `escalate` / `bind` を別にしている
  のと同じ考え）: 代わりに「`role:grant` のような専用の権限を持てば何でも配れる」形も
  考えたが、その権限 1 つが実質の `admin` になり、何を配れるかが画面から読めなくなる。
  範囲で決めれば、配れるものは自分の権限を見れば分かる。
- **格上に触れない**: パスワードを書き換えられれば、その人の権限は丸ごと取れる。
  ロールの付け外しだけを守っても穴が残る。
- **自分は変えられない**: 締め出しの事故を防ぐのと、権限の変更に必ず別の人の手を
  通すため。名前とパスワードは権限を動かさないので止めない。
- **最後は DB で数える**: アクセストークンは DB を引かずに寿命まで通る（ADR-0041）。
  ロールを外された人の古い 1 枚でも、範囲の関門は通り抜けうる。いまの状態を数える
  関門が要る。数える対象を `admin` ロールの名前にしないのは、ロール名で認可を分岐
  しない原則（CLAUDE.md「権限管理」）に従うため。

## 影響

- `user-admin` は自分の権限の範囲のロールしか配れない。雛形では `member` と同じ閲覧の
  権限を持たせ、`member`・`guest`・`user-admin` を配れるようにしてある。`manager`・`admin`
  への引き上げは、それを持つ人の仕事になる。派生アプリでロールを組み替えるときも、
  「人の係に何を配らせたいか」に合わせて閲覧の権限を持たせる。
- 新しい誤りの応答: 403 `beyond_your_permissions`（`permissions` に足りない権限）、
  403 `cannot_change_yourself`、409 `last_administrator`。
- 雛形の 3 ロールはマイグレーション 0011 で足す（`seed_master_data` の再実行。ADR-0024）。
  固定の id（5〜7）が運用中に足したロールで埋まっていれば、採番に任せる。
- この ADR に含めないもの（必要になった派生アプリで足す）: 資源ごとの範囲
  （プロジェクト単位の付与）、グループへのロールの付与、期限付きの昇格。
