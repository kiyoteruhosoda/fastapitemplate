# ADR-0098: example はアイテムの更新・削除・時刻・404 まで揃えた見本にする

- 日付: 2026-10-31
- 状態: 承認

## 文脈

`bounded_contexts/example` は「Item CRUD」と書いてあるが、作成と一覧しか無く、時刻の列も無い。新機能を書く人が最初に読む場所で、足りない部分を各自が別の形で作ることになる（task #799）。

## 決定

1. **`PUT /api/items/{id}` と `DELETE /api/items/{id}` を足す。** どちらも `item:write`。
2. **無い ID も、ほかのテナントの ID も 404（`item_not_found`）。** 引くときに必ずテナントで絞り、区別しない。
3. **ドメイン例外に `code` を持たせ、コンテキストの `error_handling.py` で HTTP に変える**（notes と同じ形）。
4. **削除は行を消す（論理削除にしない）。** 確認の画面は挟まない（notes と同じ）。
5. **`created_at` / `updated_at` は naive UTC の列**（`utcnow`。CLAUDE.md「時刻の契約」）で、更新は `onupdate` に任せる。既にある行には移行した時刻を入れる。

## 理由

- 404 に揃えるのは、403 にするとほかのテナントにその ID があることを教えるため（ADR-0078 §6 と同じ）。
- 論理削除は見本には重く、残す理由があるアプリがそこで足せばよい。

| 採らなかった案 | 捨てた理由 |
|---|---|
| 更新・削除も notes を見てもらう | notes は持ち主と共有で可否が変わる見本で、いちばん小さな形として読めない |
| 既にある行の時刻を空にする | 列を NULL にできると、読む側すべてに分岐が要る |

## 影響

- `items` の ER 図が変わる。派生アプリで見本を消しているときの扱いは `docs/CHANGELOG.md`。
