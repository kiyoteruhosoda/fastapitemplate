# ADR-0043: IdP で止まった人は、定期的に聞き直して **SSO の入口だけ**止める（定期照合）

- 日付: 2026-09-16
- 状態: 承認
- 関連: ADR-0036（停止の通知の受け口）、ADR-0039（ローカル口座を意図して持つ）、
  ADR-0041（アクセストークンは 5 分）、ADR-0021（定期実行の足回り）、ADR-0025（`private_key_jwt`）、
  ADR-0029（機械の**受け口**は入れない）、idp の ADR-0049 I7 / ADR-0057（アプリの名簿を引く口）、
  nolumiawiki の ADR-0097 / ADR-0098（先に入った 1 本）

## 文脈

idp の ADR-0049 I7 は「IdP で止めた人が RP でも止まる」を 3 つで塞ぐと決めている。

| | この雛形 |
|---|---|
| back-channel logout の受け口 | ✅ ADR-0036 |
| 短命のアクセストークン | ✅ ADR-0041（5 分） |
| **定期照合** | ⬜ **これが無い**（`docs/Progress.md` の T12） |

⚠ **受け口は、通知が届いたときにしか効かない。** assay が送れなかった・こちらが落ちていた・
送り先が登録されていなかった ——どれも取りこぼしがそのまま残る。本番の assay では
送り先の登録が 2026-09-16 まで 0 件だった。

聞く相手は 2026-09-16 にできた。assay の `GET {issuer}/admin/applications/self/users` は、
**呼んできたサービスアカウントが結び付いているアプリ**の名簿を、`sub` ごとに 3 つの状態で返す
（`allowed` / `blocked` / `unknown`）。先に nolumiawiki へ入れて本番で動かし（ADR-0097 / ADR-0098）、
形が固まったので雛形へ戻す。

⚠ **nolumiawiki の形をそのまま持ってこられない点が 1 つある。** あちらは SSO 専用なので、
止める＝`is_active = False` にした。この雛形は**ローカル口座を意図して持つ**（ADR-0039）。
同じことをすると、IdP で止まった人が**このアプリのパスワードでも入れなくなる** ——ADR-0036 の
決定 4（ローカルのログインには停止の伝播を届かせない）と食い違う。加えて nolumiawiki の形は
**戻せない**: assay で戻しても `is_active` は落ちたままで、管理者が手で戻すまで入れない
（ADR-0097 の「次の周回で戻る」は実装されていなかった）。

## 決定

**毎時 assay に名簿を聞き、止まった人・消えた人の SSO のセッションを、停止の通知が届いたのと
同じ記録で失効させる。利用者そのもの（`users`）には触らない。**

### 1. 聞く先と、状態ごとの扱い

```
GET {OIDC_ISSUER}/admin/applications/self/users?subs=<結び付いている sub を 100 件ずつ>
Authorization: Bearer {MACHINE_CLIENT_ID で client_credentials ＋ resource={issuer}/admin}
```

| `state` | こちらの扱い |
|---|---|
| `allowed` | 触らない |
| `blocked` | その利用者の **SSO のセッションをすべて失効**（`federated_session_revocations` に `sid` の無い行） |
| `unknown` | 同じく失効 ＋ **結び付き（`federated_identities`）を外す** |
| 知らない値・名簿に無い | 触らない |

- ⚠ **経路にアプリを書かない**（nolumiawiki の ADR-0098）。どのアプリの名簿かは、
  名乗ったサービスアカウントから assay が決める
- ⚠ **`is_active` を落とさない。** ローカルの入口（パスワード・パスキー）は残る。SSO の新しい
  ログインは assay 自身が断るので、ここで止めるのは**既に発行済みのセッション**だけで足りる
- ⚠ **戻せば戻る。** 失効の記録は「その時刻より前に始まったセッション」にしか効かない（ADR-0036）。
  assay で戻した人が入り直したセッションは巻き添えにしない

### 2. ⚠ 引けなかったら何もしない

404・5xx・タイムアウト・トークンが取れない ——どれも「全員辞めた」ではない。止めてよいのは
`200` で返った中身に基づくときだけ。⚠ **403 は「このサービスアカウントがまだアプリに結び付いていない」**
（準備待ち）なので warning にせず、info を 1 行残して見送る。

### 3. ⚠ 全員が `unknown` なら何もしない

結び付きが 2 件以上あって、**返ってきた全員が `unknown`** なら、結び付きを外さず見送る（warning）。
テナントを取り違えた発行者やアプリの付け替えでも、この形で返りうる。⚠ **結び付きは本人の操作でしか
作り直せない**（ADR-0040）ので、取り違えで全員分を外すと戻すのが高くつく。1 件だけのときは
区別が付かないので通常どおり扱う。

### 4. 同じ失効を何度も書かない

失効の `jti` を **`(issuer, sub, 最後に SSO で入った時刻)` から決める**。

- 同じログインに対しては毎時・ワーカーの数だけ走っても**行は 1 本**（2 本目は `jti` の重複で弾かれる）
- assay で戻って入り直し、また止められたときは、時刻が変わるので**新しい行**になる
  ——古い行は新しいセッションに効かないので、書き直さないと取りこぼす
- 同時に 2 つのワーカーが同じ行を書いてぶつかったら、その周回は巻き戻して見送る（相手が同じ行を書いている）

### 5. 名乗りは `MACHINE_CLIENT_ID`（新設）

- assay で**このアプリのサービスアカウント**として登録した `client_id`。ログイン用の `OIDC_CLIENT_ID` とは別の登録
- 鍵は `OIDC_PRIVATE_KEY_FILE` / `OIDC_PRIVATE_KEY_KID` を共有し、⚠ **方式は常に `private_key_jwt`**
  （ログイン側が `client_secret_basic` でも、機械は秘密を持たない）
- **空なら照合は走らない。** SSO が使えて、この値があれば毎時聞きに行く
- ⚠ **名前は用途を書かない**（`RECONCILE_…` にしない）。nolumiawiki では置き場用の
  `BLOB_STORAGE_CLIENT_ID` を照合にも使うことになり、読み口だけ汎用に包み直した（ADR-0098）。
  雛形は最初から汎用の名前で持つ

## 理由

- **SSO の入口だけ止めるのは、この雛形が入口を 2 系統持つから。** 止めたのは IdP で、IdP が
  認証していたのは SSO の入口である。ローカル口座はこのアプリの管理者が持ち主で、止めるかどうかは
  こちらで決める（ADR-0039）。停止の通知（ADR-0036）と**同じ範囲**に揃えると、「届いたときと
  取りこぼしたときで止まる範囲が違う」が起きない
- **失効の記録を使い回すのは、止める仕組みを 2 つ持たないため。** 検証の側（更新のたびに
  `is_revoked` を引く。ADR-0041）には手を入れずに済み、「止めたら効くまで」の上限もアクセストークンの
  寿命（5 分）のまま変わらない
- **状態を持たないので、戻すのに手が要らない。** nolumiawiki の形は「誰が止めたか」を覚えていないので
  自動で戻せない。記録は時刻で効くので、戻す操作そのものが要らない
- **全件を毎回聞く。** 名簿の口に差分（`updated_since`）は無い ——外された割り当ては差分に出ない。
  照合がいちばん拾いたい変化が、差分にはいちばん出ない

### 捨てた案

- **nolumiawiki と同じく `is_active = False` にする。** ローカルのパスワードまで止まり、ADR-0036 と
  範囲が食い違う。戻すにも管理者の手が要る
- **`LOCAL_LOGIN_ENABLED` で分ける**（閉じていれば利用者ごと止める）。画面の設定 1 つで照合の意味が
  変わり、切り替えた時点で止まっている人の扱いが決まらない
- **`unknown` の人を削除する。** 作成者・更新者の記録が切れる。止めるのと消すのは別
- **毎周回、新しい `jti` で書く。** 止まったままの人 1 人につき、リフレッシュトークンの寿命（14 日）の
  あいだ毎時・ワーカー数ぶん行が積もる
- **照合専用の設定（`SSO_RECONCILE_CLIENT_ID`）を作る。** nolumiawiki で作って消した（ADR-0098）

## 影響

- **設定が 1 つ増える**（`MACHINE_CLIENT_ID`）。テーブルは増えない
- ⚠ **有効にするには assay 側の 2 手が要る**: サービスアカウントを登録（`client_credentials` ＋
  このアプリの公開鍵）し、アプリの詳細画面の「このアプリの名乗り」に結び付ける。
  手順は `docs/OPERATIONS.md`
- ⚠ **最後の管理者の歯止め（nolumiawiki の決定 4）は持たない。** 利用者を止めないので締め出しが起きない
  ——SSO でしか入れない管理者が IdP で止まったら、その人は IdP で止まっているのであって、
  こちらが止めたのではない
- **ADR-0029（機械の受け口は入れない）とは別の話。** 入れたのは**こちらから assay を呼ぶ**名乗りで、
  このアプリに機械が入ってくる口ではない
- **派生アプリへ配るときは、自分の入口の形で「止める」の意味を決め直す。** SSO 専用のアプリ
  （ADR-0039 の 1 を選んだもの）でも、この形のままで実質は止まる（新しいログインは assay が断る）
