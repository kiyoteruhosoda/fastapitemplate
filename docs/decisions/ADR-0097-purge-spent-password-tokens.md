# ADR-0097: 使えなくなったパスワード再設定トークンは、設定なしで定期的に消す

- 日付: 2026-10-31
- 状態: 承認

## 文脈

`password_reset_tokens` は使用済みと期限切れの行が残り続ける（task #798）。ログの掃除（ADR-0075 §3）は常駐スレッドで回っているが、既定は「削除しない」で、ログの設定に従う。

## 決定

1. **`used_at` が入った行と `expires_at` を過ぎた行を、6 時間ごとに消す。** 既定で動き、設定は持たない。
2. **作りはログの掃除と同じ `start_interval_worker`。** ただしジョブは分ける（`password_token_purge.py`）。
3. 消した行数はアプリログへ残す。何も消さなかった回は書かない。

## 理由

- ジョブを分ける: ログの掃除に足すと、「ログの保持を変えない運用（既定）」でトークンも消えなくなるか、ログの掃除の中に保持期間と関係ない分岐が入る。
- 設定を持たない: 使えなくなった行に残す価値が無い。誰がいつ再設定を頼んだかは監査ログに残っている。

| 採らなかった案 | 捨てた理由 |
|---|---|
| ログの掃除のユースケースに足す | 上のとおり。ログの保持が既定（削除しない）のときの扱いが歪む |
| トークンを発行するときに消す | 発行が無いと消えない。`refresh_sessions` はログインのたびに通るのでこの形でよいが、再設定はめったに通らない |
| 主キーで小分けに消す | 行が少ない（再設定の回数しか増えない）。1 文で足りる |

## 影響

- 既に溜まっている行は、配った直後の起動で 1 回消える。
- 期限切れの招待も消える。招待の状態を画面に出しているものは無く、招待し直せば新しい行ができる。
