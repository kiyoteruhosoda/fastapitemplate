# ADR-0012: 設計品質の定量基準を Ruff と AST テストで機械検証する

- 日付: 2026-07-30
- 状態: 承認

## 文脈

CLAUDE.md は設計品質の定量基準（ネスト深度 3・関数長 30 行・引数 3 個・複雑度 10・
クラス長 200 行）を挙げていたが、Backend ではどれも機械検証されていなかった。
ADR-0006 で採用した Ruff の `select`（`E, F, I, B, UP, SIM, C4, ARG, N, RET, PTH, RUF`）に
該当ルールが入っていないためで、基準はレビュー時の観点にとどまっていた
（Frontend は `sonarjs/cognitive-complexity`（15）が複雑度のみ見ている）。

閾値を決めるには既存コードの違反数が必要だったため、まず計測した（165 ファイル・
関数 407 個・クラス 128 個）。

| 基準 | 閾値 | 違反数 | 内訳 |
|---|---|---|---|
| 複雑度（`C901`） | 10 | **0** | 5 まで下げると 5 件（うち 1 件は 9） |
| 分岐数（`PLR0912`） | 8 | **0** | — |
| 文の数（`PLR0915`） | 30 | **0** | — |
| 引数数（`PLR0913`） | 3 | 16 | src 10 / tests 6 |
| 引数数（`PLR0913`） | 4 | 2 | `list_logs`(5)・`RestartRequestStore.save`(5) |
| ネスト深度 | 3 | 1 | `_imported_modules`（5 段） |
| クラス長 | 200 行 | 1 | `ApplicationSettings`（210 行） |
| 関数長 | 30 行 | 11 | 移行スクリプト 2 件を含む。最長 86 行 |

## 決定

**基準どおりの閾値で導入し、違反している既存コードを直す。**「緩い値で入れて
段階的に締める」案は採らない（計測の結果、ほとんどの基準が違反 0 だったため）。
検証は 2 か所に分ける。

- **Ruff**（`pyproject.toml`）: `C901`(10) / `PLR0912`(8) / `PLR0913`(4) / `PLR0915`(30)。
- **AST テスト**（`tests/unit/test_design_metrics.py`）: ネスト深度 3・クラス長 200 行。
  対応する Ruff ルールが無いため、`test_layer_dependencies.py` と同じ方式で検査する。

基準に対して機械検証の閾値をずらすのは 2 点だけで、理由は下記のとおり。

- **引数数は 3 ではなく 4 で検証する。**
- **関数長は行数ではなく文の数（`PLR0915` 30）で検証する。**

`make check` / CI のコマンドは変わらない（`ruff check` と `pytest` に相乗りする）。

## 理由

- **引数 4。** Ruff は `Depends()` による依存注入・FastAPI のクエリパラメータ・
  キーワード専用の任意引数も 1 個として数える。これらは「引数が多い＝責務が多い」という
  基準が問題にしている複雑さとは別物で、3 で強制すると
  `webauthn_relying_party`（暗号パラメータ 4 個）のような妥当な署名まで落ちる。
  一方 5 個以上は 2 件しかなく、どちらも実際に直すべき状態だった（下記「影響」）。
  レビュー上の基準は 3 のまま据え置き、機械検証は「5 個以上を止める」線に置く。
- **関数長は文の数で代替。** 行数を数えると、日本語の docstring・複数行の型注釈・
  折り返した引数リストが違反として現れる。これは「コードを短く保つ」意図と逆に働き、
  説明を削る圧力になる。移行スクリプト（`op.create_table` を並べた `upgrade`）は
  86 行だが文は数個で、行数で測る意味が薄い典型。`PLR0915`（文 30）は違反 0 で入り、
  「30 行の関数はおおむね文 30 個以下」という対応が取れる。
- **テストの引数は対象外**（`per-file-ignores`）。pytest の関数引数はフィクスチャの
  注入であり、設計上の引数の多さではない（既存の `ARG001` / `ARG002` の除外と同じ理由）。
- **例外は「理由付きで 1 か所に集める」形にする。** `ApplicationSettings`(210 行) は
  設定キーの数に比例して伸びる `@property` の集まりで、分割すると「設定は
  `settings.py` の `@property` 経由」という規約の出所が散る（CLAUDE.md「設定管理」）。
  ミックスインへ分ける案は、この一点のためにアクセサの一覧を分断するので採らなかった。
  例外はテスト内の `_CLASS_LENGTH_EXEMPTIONS` に理由文とともに置き、
  **消えたクラスが例外に残らないことも**テストで検証する。
- 捨てた代替案:
  - **`PL` ルール群をまとめて有効化** — `PLR2004`（マジックナンバー）など、設計品質の
    定量基準とは無関係なルールが大量に入る。基準に対応する 4 つだけを選ぶ。
  - **緩い閾値（複雑度 15・引数 5）で導入して段階的に締める** — 実測が 0 件なのに
    緩めると、基準を満たさないコードが入る余地をわざわざ作ることになる。
  - **`radon` / `xenon` などの外部ツールを追加** — 関数長とクラス長は測れるが、
    ツールが 1 つ増え CI のステップも増える。Ruff で足りない 2 項目は AST テストで
    十分に書ける（すでに同じ方式の依存方向テストがある）。
  - **Frontend も同じ閾値に揃える** — ESLint 側は `sonarjs/cognitive-complexity`(15) が
    別の尺度（認知的複雑度）で動いている。揃えるかどうかは別途判断する。

## 影響

- 基準に合わせて既存コードを 3 か所直した。
  - `presentation/fastapi/routers/admin/logs.py`: クエリパラメータ 4 個を
    `LogSearchRequest`（`Annotated[..., Query()]`）へまとめ、引数 5 → 2 個。
    **OpenAPI 上のクエリパラメータは変わらない**（`limit` / `offset` / `level` / `request_id`）。
  - `shared/kernel/restart/request.py`: `save()` の `requested_at` 引数を削除（引数 5 → 4）。
    **どこからも渡されていない引数**で、テストで時刻を固定する手段としても
    CLAUDE.md の方針（`datetime.now` を patch する）と食い違っていた。
  - `tests/unit/test_layer_dependencies.py`: `_imported_modules` の 5 段ネストを、
    `from` の解決を別関数（`_imported_from`）に出して 2 段に下げた。
- **これから追加するコードは 5 個以上の引数・複雑度 11 以上・文 31 個以上・
  ネスト 4 段・200 行を超えるクラスを書けない。** 分割できない事情があるときは
  `# noqa: <rule>` に理由を添えるか、例外リストへ理由付きで加える。
- 検証範囲は mypy の `files` と同じ（テスト自身も含む）。新しいトップレベル
  パッケージを追加したら、`pyproject.toml` の `files` と AST テストの
  `_SOURCE_ROOTS` の両方に足す必要がある。
