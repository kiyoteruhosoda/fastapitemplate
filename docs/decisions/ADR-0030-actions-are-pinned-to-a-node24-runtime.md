# ADR-0030: GitHub Actions は Node 24 で動く版に上げ、動く major タグが無いものだけ完全な版で固定する

- 日付: 2026-09-04
- 状態: 承認

## 文脈

CI の実行に注釈が出ていた。

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being
forced to run on Node.js 24: astral-sh/setup-uv@v6.
```

GitHub のランナーは Node 20 を落とし、`node20` を要求する action を Node 24 で
**強制的に**動かしている。今は動いているが、これは互換性のための猶予であって、
action 側が Node 24 で試していない保証は無い。猶予が切れれば止まる。

**注釈にしか出ない。** チェックは緑のままなので、ログを開かないと気付けない。

このリポジトリで `node20` を要求していたのは 3 つ。

| action | 版 | 実行時 |
|---|---|---|
| `astral-sh/setup-uv` | `@v6` | `node20` |
| `docker/setup-buildx-action` | `@v3` | `node20` |
| `docker/build-push-action` | `@v6` | `node20` |

`actions/checkout@v6` と `actions/setup-node@v6` は既に `node24`。

上げるにあたって困ったのは `setup-uv` で、**v8 以降は `@v8` のような動く major
タグを発行しなくなった**。理由は上流が明記している —— 動くタグは差し替えられる
ため、`tj-actions` の事件のようなサプライチェーン攻撃の入口になる。

## 決定

**3 つとも Node 24 で動く版へ上げる。動く major タグがあるものはそれを使い、
無いものだけ完全な版で固定する。**

| action | 版 | 固定の仕方 |
|---|---|---|
| `astral-sh/setup-uv` | `@v10.0.1` | **完全な版**（上流が major タグを出していない） |
| `docker/setup-buildx-action` | `@v4` | 動く major タグ |
| `docker/build-push-action` | `@v7` | 動く major タグ |

`setup-uv` の行には、**なぜここだけ書き方が違うのか**をワークフローにコメントで
残す（このリポジトリはテンプレートなので、派生側が「揃っていない」と見て直して
しまわないようにする）。

## 理由

**強制実行は仕様ではなく猶予。** 「今は動いている」を根拠に据え置くと、猶予が
切れた日に CI が全部止まる。しかも予告は注釈にしか出ない。

**上流が major タグを出していないものを、無理に揃えない。** 見た目を `@v10` で
揃えるには、こちらでタグを作るか古い版に留まるしかない。前者は上流が避けたかった
「差し替えられるタグ」を自分で復活させることになり、後者は Node 20 の版
（`@v7`）に据え置くことになって、この ADR の目的そのものを失う。**書き方の
不揃いは、固定の強さが違うという事実の反映**であって、直すべき乱れではない。

**全部を完全な版で固定する案は採らない。** 一貫はするが、`checkout` や
`setup-node` まで手で追うことになり、テンプレートの利用者に月次の追随作業を
押し付ける。動く major タグを出している action は、上流がその運用を選んでいる
（パッチを自動で配る）のだから、それに乗る。

**Dependabot に任せる案は今は採らない。** 追随の自動化は正しい方向だが、
`.github/dependabot.yml` を足すのは別の決定（更新の頻度・まとめ方・レビューの
負荷）で、Node 20 を落とす話とは切り離す。

## 影響

- **`setup-uv` の版を上げるのは手作業になる。** `@v10.0.1` は自分では動かない。
  上げ忘れてもすぐには壊れないので、気付く仕掛けが要るなら Dependabot を
  別途足す（上記のとおり本 ADR の範囲外）。
- **`prune-cache` の既定が `false` になった**（`setup-uv` v9 の破壊的変更。
  PyPI の負荷を下げるため）。Actions のキャッシュ使用量は増えるが、キャッシュは
  リポジトリ単位で上限まで LRU で回るだけなので、明示的な設定は足さない。
- **`v6 → v10` は破壊的変更を 3 つまたぐ**が、このリポジトリはどれにも触れていない
  —— 廃止された `server-url` 入力（v7）と旧 `manifest-file` 形式（v8）は未使用、
  `pull_request_target` / `workflow_run` / `release` でのキャッシュ自動無効化
  （v10）は該当するトリガーを使っていない（ADR-0009）。
- **docker の 2 つも破壊的変更をまたぐ**が同様。廃止された入出力と
  `DOCKER_BUILD_NO_SUMMARY` / `DOCKER_BUILD_EXPORT_RETENTION_DAYS` は未使用。
- **セルフホストのランナーでは動かない可能性がある。** docker の 2 つは
  Actions Runner v2.327.1 以降を要求する。このリポジトリの CI は
  GitHub ホストのランナーで動くので影響しないが、**派生アプリをセルフホストの
  ランナーへ載せている場合は、先にランナーを更新すること**。
