# ADR-0067: 前段が 503 で閉じていると答えたら、アプリ内のメンテナンス画面に切り替える

- 日付: 2026-10-23
- 状態: 承認

## 文脈

公開名の前段（edge）は、計画メンテナンスの宣言があるホストへの要求すべてに 503 を返す
（nolumiatask #653・#654・#663）。ブラウザ（`Accept: text/html`）には edge のメンテナンス画面、
それ以外には JSON を返す:

```json
{"error":"service_unavailable","reason":"maintenance","until":"2026-10-28T19:30:00Z",
 "message":"<理由>","title":"<見出し>","body":"<本文>"}
```

上流（このアプリ）が居ないだけのときは `{"error":"service_unavailable","reason":"stopped","host":"…"}`。
`title`・`body` は #663 で足したので、古い edge は返さない。edge は JS・CSS にも 503（JSON）を返す。

⚠ **この画面は PWA なので、edge のメンテナンス画面は見えない。** 画面の移動では Service Worker が
手元の index.html を返す（`navigateFallback`）。読み込み直しても同じで、利用者は「ログインできない」
「サーバーにつながりません」としか分からない。

## 決定

1. API の応答が 503 で、本文の**最上位**が `error: "service_unavailable"` かつ `reason` が
   `maintenance` / `stopped` なら「前段が閉じている」と読む（`frontend/src/services/maintenance.ts`）。
   アプリ自身のエラー（`{"detail": {"error": …}}`）とは形で見分ける。読むのは API の入口（`api.ts`）と、
   最初に読む画面の設定（`uiSettings.ts`）。
2. 閉じている間は、アプリの画面を**消さずに隠し**、別の React の root にメンテナンスの画面を描く。
   見出し・本文は edge の文言、無ければ既定の文（`maintenance` は「メンテナンス中」、`stopped` は
   「停止中」）。理由（`message`）と戻りの見込み（`until` を閲覧者の時間帯で）も出す。
3. 画面は 1 分ごと・タブが手前へ戻ったとき・「いま確かめる」を押したときに `GET /api/ui/settings` で
   確かめ直す。通ればアプリの画面へ戻す（読み込み直さない。認証は聞き直す）。ほかの API の答えが
   返ったときも戻す。
4. 閉じている間はエラーのトーストを出さない。ログインの聞き直し（5 秒ごと）も止める。
5. 遅れて読み込む部品（動的 import の JS・CSS）が読めなかったとき（Vite の `vite:preloadError`）は、
   閉じているかを確かめ、閉じていれば同じ画面を出して、開いたら読み込み直す。ただの失敗なら
   何もしない（`preventDefault` しない。エラーは今までどおり投げられる）。

## 理由

- **API の応答で切り替える。** 画面の移動は Service Worker が答えるので、edge の画面を見せる道は無い。
  Service Worker の中で 503 を見て差し替える案は、手元の index.html を返すという PWA の働き
  （オフラインでも開く）を崩し、Service Worker の写しの更新（ADR-0035）とも絡むので採らない。
- **別の root に描く。** 部品が欠けてアプリの木が落ちても出せる。アプリの木の中に置くと、
  エラーの境界（ErrorBoundary）を全部の画面に要求することになる。
- **隠すだけにする。** 戻ったとき、入力の途中も画面の位置もそのまま戻る。
- **確かめ直しは 1 分ごと。** 宣言は数分〜数十分の単位で、`Retry-After` は 300 秒。上流が居ないだけの
  ときも同じ間隔にし、待てない人のために「いま確かめる」を置く。
- **部品の失敗は確かめてから決める。** 読めなかった理由が 503 かどうかは、`vite:preloadError` からは
  分からない。決め付けるとふつうの失敗（回線・古い版の部品）までメンテナンスに見せてしまう。
- **文言は edge のものを優先する。** 何が起きているかを書けるのは宣言した人だけ。edge の画面は
  英語だけ（#653 の決定）なので、既定の文だけは画面の言語で出す。

## 影響

- このテンプレートから作ったアプリへ配るのは別の課題（各アプリへ 1 本ずつ。#653）。
- 新しい API の入口を `api.ts` を通さずに作ると、503 を受けても切り替わらない。
- 前段が自前の 503 の形を変えたら `outageFrom` を合わせる。アプリが自分で
  `{"error":"service_unavailable","reason":"maintenance"}` を最上位に返すと、同じ画面になる。
- 実ブラウザの試験（`frontend/e2e/maintenance.spec.ts`）は、edge の代わりに API へ同じ形の 503 を返す。
  その応答は見張り（`e2e/fixtures.ts`）が 5xx として数えないよう印を付ける。
