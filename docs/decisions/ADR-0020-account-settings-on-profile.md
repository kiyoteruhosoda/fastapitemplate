# ADR-0020: 本人のアカウント設定はプロフィールとセキュリティの 2 画面に分ける

- 日付: 2026-08-01
- 状態: 承認

## 文脈

本人が自分に対して行う設定が 3 つの画面に分かれていた。

| 画面 | ルート | 内容 |
|---|---|---|
| プロフィール | `/profile` | メールアドレス・表示名、言語・テーマ、ロール、scope |
| パスワード変更 | `/change-password` | 現在／新しいパスワード |
| セキュリティ | `/security` | 二要素認証（TOTP）・パスキー |

3 つとも「サインイン中の本人だけが対象・必要 scope なし・入口はヘッダーの
ユーザー名だけ」で、サイドバーにも出ない。にもかかわらず、パスワード変更と
セキュリティへはプロフィールの下端のリンクからしか辿れず、パスワード変更に
至っては欄が 2 つあるだけの画面だった。「サインインの手段を変えたい」だけで
画面を 2 回移動する必要があり、どこに何があるのかも画面名からは分からない。

一方、3 画面ぶんを 1 ページへ寄せると区画が 7 つになり、狭い画面では縦に長く
なりすぎて目的の設定に辿り着けない（一度そう作って確かめた）。

## 決定

**関心ごとに 2 画面へ分け、親子（プロフィール → セキュリティ）にする。**

| 画面 | ルート | 区画 |
|---|---|---|
| プロフィール | `/profile` | アカウント、セキュリティ（入口）、表示設定、ロール、有効なスコープ |
| セキュリティ | `/profile/security` | パスワード変更、二要素認証、パスキー |

- 「パスワード変更」は独立した画面をやめ、セキュリティの区画にする。パスワード・
  二要素認証・パスキーは**どれも「どうやってサインインするか」という 1 つの関心**で、
  分ける理由が無い。
- 入口はヘッダーのユーザー名 → プロフィールの「セキュリティ」区画（見出し・説明・
  リンク）だけ。セキュリティ画面からはプロフィールへ戻るリンクを置く。
- 旧 URL（`/change-password`・`/security`）は `/profile/security` へ転送する。

## 理由

- **画面を分ける単位は「関心」であって「操作」ではない。** 旧構成はパスワード変更
  という 1 操作に 1 画面を与えていた。新構成では、変えたいもの（自分は誰か／
  どうサインインするか）で分かれる。
- **1 画面に全部載せる案は採らなかった。** 区画 7 つは縦に長く、狭い画面では
  スクロールしないと何があるのか分からない。
- **タブに分ける案も採らなかった。** URL が変わらない切り替えは、ブックマーク・
  再読み込み・戻るの挙動を自分で面倒みることになる。素直に画面（ルート）で
  分ければブラウザの機能がそのまま使える。
- **サイドバーに「セキュリティ」を足す案も採らなかった。** サイドバーは scope で
  出し入れする業務メニューで、全員に必ず出る本人設定を混ぜると「表示はロール名
  ではなく scope で決まる」という規則が崩れる。
- 旧 URL を 404 にせず転送するのは、ブックマークや過去のリンクの行き止まりを
  作らないため。

## 影響

- 画面が 1 つ減る（旧 S7 パスワード変更が無くなり、旧 S8 セキュリティが
  S7 `/profile/security` になる）。以降の採番が 1 つ繰り上がる（旧 S9〜S15 →
  S8〜S14）。`frontend/README.md` の画面遷移図・画面一覧・画面仕様・
  操作マニュアルが対象。
- 区画の中身は再利用できる部品にした（`components/PasswordChangeForm.tsx`・
  `TwoFactorControls.tsx`・`PasskeyControls.tsx`）。区画の見出しと枠は呼び出し側の
  画面が持つ（`PreferenceControls` と同じ形）。どの画面にどの区画を置くかは
  画面側だけを見れば分かる。
- 区画の CSS クラスは 2 画面で共有するので `.profile-section` / `.profile-form`
  ではなく `.settings-section` / `.settings-form` とする。
- API は変えない（呼ぶ画面が変わっただけ）。
