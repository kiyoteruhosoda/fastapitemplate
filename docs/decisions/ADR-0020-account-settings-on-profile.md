# ADR-0020: 本人のアカウント設定はプロフィール 1 画面に集約する

- 日付: 2026-08-01
- 状態: 承認

## 文脈

本人が自分に対して行う設定が 3 つの画面に分かれていた。

| 画面 | ルート | 内容 |
|---|---|---|
| プロフィール | `/profile` | メールアドレス・表示名、言語・テーマ、ロール、scope |
| パスワード変更 | `/change-password` | 現在／新しいパスワード |
| セキュリティ | `/security` | 二要素認証（TOTP）・パスキー |

3 つとも「サインイン中の本人だけが対象・必要 scope なし・入口はヘッダーの
ユーザー名だけ」で、サイドバーにも出ない。にもかかわらず、パスワード変更と
セキュリティへはプロフィールの下端のリンクからしか辿れず、どちらも 1〜2 区画しか
持たない小さな画面だった。「サインインの手段を変えたい」だけで画面を 2 回移動する
必要があり、どこに何があるのかも画面名からは分からない。

## 決定

`/change-password`（旧 S7）・`/security`（旧 S8）を独立した画面として持つのをやめ、
プロフィール（S6）の区画にする。中身は再利用できる部品として `components/` に置き、
プロフィールが区画の見出しと枠を与えて並べる。旧 URL は `/profile` へ転送する。

区画の並び: アカウント → パスワード変更 → 二要素認証 → パスキー → 表示設定 →
ロール → 有効なスコープ（「自分は誰か」→「どうサインインするか」→「どう見せるか」→
「何ができるか」の順）。

## 理由

- **画面を分ける根拠が無かった。** 画面を分けるのは、対象が違う・必要 scope が
  違う・一度に見せると多すぎる、のいずれかのとき。3 つはどれにも当たらない
  （同じ本人・scope なし・合計 7 区画）。
- **入口が 1 つになる。** ヘッダーのユーザー名から辿れる先が「自分の設定」の
  すべてになり、リンクを辿らせる必要が無くなる。プロフィールの下端にあった
  リンクの並びも消える。
- **代替案「サイドバーに『セキュリティ』を足す」を採らなかった。** サイドバーは
  scope で出し入れする業務メニューで、全員に必ず出る本人設定を混ぜると
  「scope で決まる」という規則が崩れる。
- **代替案「タブに分ける」を採らなかった。** 区画は 7 つで、縦に並べても
  長すぎない。タブは状態（いまどのタブか）が増えるだけで、得るものが無い。
- 旧 URL を 404 にせず転送するのは、ブックマークや過去のリンクの行き止まりを
  作らないため。

## 影響

- 画面 S7・S8 が無くなり、画面一覧の採番が繰り上がる（旧 S9〜S15 → S7〜S13）。
  `frontend/README.md` の画面遷移図・画面一覧・画面仕様・操作マニュアルが対象。
- `pages/ChangePasswordPage.tsx` と `pages/SecurityPage.tsx` は無くなり、
  `components/PasswordChangeForm.tsx`・`components/TwoFactorControls.tsx`・
  `components/PasskeyControls.tsx` になった。区画の見出しは呼び出し側が持つ
  （`PreferenceControls` と同じ形）。
- プロフィールを開くと二要素認証の状態とパスキーの一覧も取りに行くので、この画面の
  初回リクエストが 1 本から 3 本に増える。本人設定の画面で頻繁に開くものではなく、
  区画ごとの遅延読み込みは入れない。
- API は変えない（呼ぶ画面が変わっただけ）。
- i18n の `security.title` は使わなくなったので消した。区画の見出しには
  `changePassword.title`・`security.twoFactor`・`security.passkeys` を使う。
