# ADR-0052: 全権限のロールは `owner` と呼ぶ

- 日付: 2026-10-05
- 状態: 承認

## 文脈

ADR-0051 でロールを系統で分け、`system-admin`・`user-admin` を足した。全権限のロールは
`admin` のまま残したので、`admin` と `system-admin`・`user-admin` の関係が名前から
読めなくなった。`admin` が全部を持つ上位なのか、ほかと並ぶ 1 つの係なのかが分からない。

## 決定

全権限のロールの名前を `admin` から `owner` へ変える（id 1 と付与はそのまま）。
系統ごとの係は `<系統>-admin` と呼ぶ。既存の DB はマイグレーション 0012 で名前の列だけを
書き換える。既定の管理者の利用者名・メールアドレス（`admin` / `admin@example.com`）は
利用者の名前なので変えない。

## 理由

- `owner` は「全部を持つ・最後の責任者」と読め、`〜-admin` の係とは別格だと名前で分かる。
  GitHub・Google Cloud・Slack も「Owner ＞ 各種 Admin」で、見慣れた並びである。
- `superadmin` も考えたが、強さしか表さず、`〜-admin` と同じ列の延長に見える。
- 名前の書き換えにするのは、`seed_master_data` が名前でロールを探すため。先に書き換えずに
  流すと、`owner` を新しい行として作り、`admin` が付与ごと残る。

## 影響

- 派生アプリで「作成者だけが直せる」という作りを足すときは、資源の側を「作成者」と呼び、
  ロールの `owner` と言葉をぶつけない。
- `active_role` に `admin` を持つ発行済みのトークンは、更新の時点で保有ロールに当たらず
  権限が空になる（ADR-0017）。そのロールに絞っていた人はサインインし直す。
  「すべてのロール」で操作している人には影響しない。
- 派生アプリが自前で `owner` を作っていたときは、マイグレーションは書き換えない
  （`admin` が残る）。付与を見て手で寄せる。
- ADR-0051 の本文で `admin` と書いているロールは、これ以降 `owner` を指す。
