# ADR-0058: ログインの失敗を宛名ごとに数え、上限を超えたらしばらく断る

- 日付: 2026-10-21
- 状態: 承認

## 文脈

パスワードのログインは失敗を監査ログに残すだけで、何度でも試せた。パスワードが分かった相手には
二要素の 6 桁のコードも何度でも試せ（前後 1 枠を許すので 1 回あたり約 33 万分の 1）、再設定の
メールも同じ宛先へ際限なく送らせられた（2026-10-21 の脆弱性確認、task #575）。
派生の deck は同じ雛形から出たあと、deck の ADR-0044 で塞いでいた。

## 決定

deck の ADR-0044 の作りをそのまま持ってくる。

- 数える単位は**送られてきた宛名**（メールアドレス。大文字小文字と前後の空白は揃える）。
  実在するアカウントとは結ばない。
- 窓（`LOGIN_FAILURE_WINDOW_SECONDS`、既定 900 秒）の中で上限（`LOGIN_MAX_FAILURES`、既定 5 回）まで
  失敗したら、`LOGIN_LOCK_SECONDS`（既定 900 秒）のあいだ **429 `too_many_attempts`** で断る
  （`Retry-After` と `retry_after_seconds` で待ち時間を返す）。正しいパスワードでも断る。
- パスワードの間違い・二要素のコードの間違いは同じ数え上げに入れる。正しく入れたら忘れる。
- 再設定メールの要求は別の籠で、**成功も数える**（成功しても相手にメールが届くため）。
- 控えは DB の `login_attempts` に置く。断り始めたことは監査ログに `login.locked` で残す。
- 未知の宛名でも、ダミーのハッシュと照合して応答時間を揃える。

## 理由

- 実在するアカウントだけを数えると、断られるかどうかで存在が分かってしまう。
- プロセスのメモリではなく DB に置くのは、Gunicorn が複数ワーカーで動くため（ワーカーの数だけ試せる）。
- 失敗の記録は 401 と一緒に返る（例外で抜ける）ので、リクエストの DB セッションに書くと rollback で
  消える。控えは自前の短いセッションで commit する。
- 401 に紛れ込ませないのは、断られていることが分からないと正しいパスワードを入れても弾かれ続けて
  「忘れた」と誤解し、再設定へ流れるため。
- 採らなかった案: 接続元 IP で数える。前段（Cloudflare・nginx）の後ろでは同じ IP に見える人が多く、
  逆に攻撃側は IP を替えられる。

## 影響

- 宛名を知っている人は、わざと間違えてその人をしばらく締め出せる（妨害）。上限と断る長さは管理画面の
  設定で変えられる。`LOGIN_MAX_FAILURES=0` で数えない（本番で 0 にしない）。
- パスキーと SSO のログインは対象外（パスワードもコードも無いので、総当たりの的にならない）。
- 移行は表を足すだけ。
