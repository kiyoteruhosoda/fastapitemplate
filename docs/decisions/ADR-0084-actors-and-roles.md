# ADR-0084: ロールはアクターから導き、設定はシステムとコンテンツの 2 層に分ける

- 日付: 2026-10-30
- 状態: 承認
- 置き換える節: ADR-0079 §3 決定 2（全体の権限の一覧）・ADR-0080 §6（縦組みの見出しの高さ）

## 文脈

ロールは ADR-0078 §4 で「扱うものの系統」（システム・人・監査・コンテンツ）に分けたが、どんな人が
このシステムを使うのかを書いた表は無く、ロールが誰のためのものかはコメントから読み取るしかなかった。
そのため次の穴が残っていた。

- 設定の権限は全体の 1 つ（`admin:system-settings`）だけで、テナントの中の決まり（コンテンツ設定）を
  誰が変えられるかを表す権限が無かった。
- 見ると変えるが 1 つの権限にまとまっていた（`admin:system-settings`・`item:manage`）。「見るだけ」の
  人（監査・サポート）を作れなかった。
- テナントの外の席は運用者（`system-admin`）だけで、問い合わせに答えるために状態を見る人の席が無かった。
- `permission:manage` は権限コードの一覧を読むことしか許しておらず、名前から何を許すのかが読めなかった。

持ち主と、使う人（アクター）→ ユースケース → 権限 → ロールの順で決めた（2026-10-30）。

## 決定

### §1 アクター

システムを使う人を先に決め、ロールは 1 つのアクターに 1 つ当てる。

| 区分 | アクター | 目的 | ロール |
|---|---|---|---|
| テナントの外 | 運用者 | アプリ全体を動かし続ける（テナントの開設と停止・システム設定・障害対応） | `system-admin` |
| テナントの外 | サポート担当 | 問い合わせに答えるため、各テナントの状態を見る | `system-support` |
| テナントの中 | テナント管理者 | 自分の組織での使い方に最終責任を持つ | `owner` |
| テナントの中 | 利用者管理者 | 組織の人を入れる・外す・役割を割り当てる | `user-admin` |
| テナントの中 | コンテンツ管理者 | コンテンツの決まり（分類・表示・保存期間）を決める | `content-admin` |
| テナントの中 | 編集者 | コンテンツを作る・直す | `manager` |
| テナントの中 | 閲覧者 | コンテンツを読む | `member`（入るだけの人は `guest`） |
| テナントの中 | 監査者 | 誰が何をしたか、設定がどうなっているかを確かめる | `auditor` |
| システム | 外部アプリ | API で決まった操作をする | （ADR-0082 の許可簿） |
| システム | IdP（Assay） | 人を認証し、テナントを知らせる | — |
| システム | 時間（定期処理） | 掃除・照合を決まった時刻に行う | — |

雛形に置くのは、どの派生アプリにも出てくるアクターだけ。それ以外は派生アプリで足す。

### §2 ユースケースと担当

◎ 変えられる・○ 見るだけ・− 触れない。

**テナントの外**

| ユースケース | 運用者 | サポート担当 |
|---|---|---|
| システム設定を見る / 変える | ◎ | − |
| システムの状態を見る | ○ | ○ |
| 再起動する | ◎ | − |
| アプリログを見る | ○ | − |
| テナントの一覧と状態を見る | ○ | ○ |
| テナントを開設・停止・削除し、最初の管理者を指名する | ◎ | − |
| テナントの外の人を足す・外す | ◎ | − |
| 全体の監査ログを見る | ○ | − |

**テナントの中**

| ユースケース | テナント管理者 | 利用者管理者 | コンテンツ管理者 | 編集者 | 閲覧者 | 監査者 |
|---|---|---|---|---|---|---|
| コンテンツ設定を見る | ◎ | − | ◎ | − | − | ○ |
| コンテンツ設定を変える | ◎ | − | ◎ | − | − | − |
| コンテンツを作る・直す・消す | ◎ | − | − | ◎ | − | − |
| コンテンツを読む | ◎ | ○ | ○ | ◎ | ○ | − |
| お知らせを配信する | ◎ | − | − | − | − | − |
| 利用者を招待・停止する・グループを管理する | ◎ | ◎ | − | − | − | − |
| ロールを付け外しする | ◎ | ◎（自分の範囲まで。ADR-0078 §4） | − | − | − | − |
| ロールの中身を定義する | ◎ | − | − | − | − | − |
| テナントの監査ログを見る | ○ | − | − | − | − | ○ |

### §3 権限は「対象:操作」で、見ると変えるを分ける

1. 設定は 2 層に分ける。**システム設定**（アプリ全体に効く。`system-settings:*`）は `SYSTEM_PERMISSIONS` に入れ、
   テナントの外の席だけが持つ。**コンテンツ設定**（そのテナントの中身の決まり。`content-settings:*`）は
   テナントの中の権限にする。
2. 見ると変えるを分ける: `system-settings:view` / `:write`、`content-settings:view` / `:write`、`item:view` / `:write`、
   `system:view`（状態）/ `system:manage`（再起動・テナントの外の人の付け外し）、`tenant:view` / `tenant:manage`。
   ⚠ **`:write` を持つロールには、同じ対象の `:view` も持たせる**（`tests/unit/test_master_data.py` が見張る）。
3. 改名と廃止:

| 前 | 後 |
|---|---|
| `admin:system-settings` | `system-settings:view` ＋ `system-settings:write` |
| `item:manage` | `item:write` |
| `permission:manage` | 廃止。権限コードの一覧は `role:manage` で読む |

4. 移行 `0020_actors_and_roles` は付与ごと名前を変え、前に変えられた人には見るほうも付ける
   （前にできたことは続けてできる）。`permission:manage` は付与ごと消す。

### §4 ロール

全員が持つ `dashboard:view` と `gui:view` は省く。

| ロール | 権限 |
|---|---|
| `system-admin` | `SYSTEM_PERMISSIONS` 全部（`system-settings:view/write`・`system:view/manage`・`log:view`・`tenant:view/manage`）、`audit:view` |
| `system-support`（新） | `system:view`・`tenant:view` |
| `owner` | テナントの中の全部 |
| `user-admin` | `user:manage`・`group:manage`・`item:view`・`note:view` |
| `content-admin`（新） | `content-settings:view/write`・`item:view`・`note:view` |
| `manager`（編集者） | `item:view/write`・`note:view/write` |
| `member` | `item:view`・`note:view` |
| `guest` | なし |
| `auditor` | `audit:view`・`content-settings:view` |

1. `system-support` は `system-admin` と同じくテナントの外の席（`SYSTEM_ROLES`）。テナントの外の人は
   どちらか 1 つを持つ。足すときにロールを選ぶ（`POST /api/system/administrators` の `role`。既定は `system-admin`）。
2. 「有効な運用者を 0 人にしない」（ADR-0079 §1）で数えるのは `system-admin`（`SYSTEM_ADMIN_ROLE`）だけ。
   サポート担当はテナントを管理できないので数えない。`scripts/create_system_admin.py` が作るのも `system-admin` だけ。
3. 編集者のロール名は `manager` のまま（ADR-0078 §4 の理由のとおり、派生アプリと発行済みのトークンが持っている）。

## 理由

- **アクターから導く**: ロールの名前や束ね方から考えると、「誰の仕事か」が抜けたまま権限が足される。
  使う人とユースケースの表を先に置けば、ロールの追加・変更は表の差分として説明できる。
- **設定を 2 層に分ける**: 被害の範囲が違う。システム設定の誤りは全テナントを止め、秘密（メール・IdP）にも
  触れる。コンテンツ設定の誤りはそのテナントの見え方が変わるだけ。同じ権限にすると、あるテナントの
  管理者がほかのテナントまで動かせる（ADR-0079 §1）。
- **見ると変えるを分ける**: 職務の分離（監査者は確かめるが変えない）とサポート担当は、見るだけの権限が
  無いと作れない。後から分けると改名の移行が要るので、雛形の段階で分けておく。
- **サポート担当に設定・アプリログ・監査ログを見せない**: アプリログと監査ログには利用者を追える情報
  （内部 ID・ハッシュ）が入り、システム設定には外部の連携先が並ぶ。問い合わせに答えるには、テナントの
  有無・停止・人数と、システムが動いているかで足りる。テナントの中身は運用者にも見せない（ADR-0079 §1）。
- **コンテンツ管理者に中身を直させない・監査者に中身を読ませない**: 系統をまたぐロールを作らない
  （ADR-0078 §4）。両方要る人にはロールを 2 つ付ける。
- **編集者にコンテンツ設定を見せない**: 編集に要る分類などは、編集画面の選択肢として出せば足りる。
- **`permission:manage` を廃止**: 一覧が要るのはロールを定義するときだけで、`role:manage` を持たずに
  一覧だけ読める人に使い道が無い。

| 採らなかった案 | 捨てた理由 |
|---|---|
| `manage` 1 つで見ると変えるを兼ねる（いまのまま） | 見るだけの人（監査・サポート）を作れない |
| 設定を 1 つの `settings:*` にまとめ、範囲を値で分ける | 権限の名前から被害の範囲が読めない。テナント管理者に配れてしまう |
| サポート担当を運用者の「見るだけ」切り替え（アクティブロール）で済ませる | 別の人が担う仕事で、運用者の権限を渡すことになる |
| コンテンツ管理者を作らず `owner` だけに設定を任せる | テナント管理者に全権限を渡さないと決まりを変えられない |
| `manager` を `editor` へ改名する | ADR-0078 §4 と同じ理由で見送る |

## 影響

- いまはコンテンツ設定を扱う画面と API が無いので、`content-settings:*` を持っていても使い道が無い。
  受け皿（テナントごとの設定の表・API・画面）は次の段で足す（`docs/Progress.md` の T16）。
- 画面: システム設定は `system-settings:view` で開け、`:write` が無ければ入力欄を止めて保存ボタンを出さない。
  テナントの画面は `tenant:view` で開け、`tenant:manage` が無ければ変える操作のボタンを出さない。
  「システム管理者」の画面は「運用者とサポート担当」になり、足すときに役割を選ぶ。
- ロールの画面の縦組みの見出しは、いちばん長い scope が `content-settings:write`（22 文字）になったので
  高さを 11rem にした（ADR-0080 §6 の 10.5rem を置き換える）。
- 発行済みのトークンが持つ前の名前（`admin:system-settings`・`item:manage`・`permission:manage`）は、
  更新の時点で取り直される（ADR-0078 §1）。それまでの最長 5 分、前の名前の口は 403 になる。サインインし直せばすぐ効く。
- 派生アプリは自動では追随しない。取り込むときは `item:manage` などを自前のコードで使っていないかを
  確かめ、使っていれば `:write` へ書き換える。自前の `<資源>:manage` も、見るだけの人が要るなら分ける。
- 派生アプリでアクターを足すときは、§1 と §2 の表に行を足してから権限とロールを決める。
