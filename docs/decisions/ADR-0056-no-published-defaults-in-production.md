# ADR-0056: 本番では、公開されている既定値（署名鍵・管理者のパスワード）で動かない

- 日付: 2026-10-21
- 状態: 承認

## 文脈

雛形には、リポジトリに載っている（＝誰でも読める）既定値が 2 つある。

- 署名鍵 `JWT_SECRET_KEY` の既定値。アクセストークンの検証は DB を引かない（ADR-0041）ので、
  この鍵で作ったトークンは**書いた権限のまま通る**。渡し忘れると、誰でも全権のトークンを作れる。
- 既定の管理者（`admin@example.com`・全権の `owner`）のパスワード。`ADMIN_INITIAL_PASSWORD` を
  渡し忘れると、公開されているパスワードのまま据わる。

どちらも警告すら出ず、雛形から新しいアプリを起こすたびに渡し忘れる機会がある
（2026-10-21 の脆弱性確認、task #573）。派生の deck は前者を自分で塞いでいた（deck の ADR-0043）。

## 決定

`APP_ENV=production` のときだけ、次の 2 つを断る。

1. 署名鍵が空・既定値・32 文字未満なら、**アプリを組み立てない（起動しない）**
   （`shared/kernel/settings/secret_guard.py`）。
2. パスワードのログインで、**公開されている既定のパスワードでは入れない**（401。理由は他の失敗と
   同じ `invalid_credentials`。監査ログの `reason` は `default_password`）。

それ以外の環境（開発・stg）は、1 は警告だけ、2 は今までどおり入れる。

## 理由

- 警告はログにしか出ず、本番のログを毎日読む人はいない。気付かせる確実な方法は動かないこと。
- 鍵は「既定値でない」だけでは足りないので長さも見る（`openssl rand -base64 48` で 64 文字）。
- 管理者は「起動しない」にすると、`ADMIN_INITIAL_PASSWORD` を渡したかを起動時に知る方法が無い
  （投入は利用者が居ないときにしか値を使わない。ADR-0024）。ログインの時点で値そのものを
  見れば、渡し忘れた環境でも、後から既定値に戻した環境でも同じように塞げる。
- 既定の管理者に限らず「その値で入ろうとしたら断る」にした。公開された値である点は誰が使っても同じ。
- 採らなかった案: 既定の管理者をパスワード無しで作る。開発の据え付け直後に入れなくなり、
  README の手順（既定のパスワードで入って変える）が崩れる。

## 影響

- 本番で既定のパスワードのまま据わった管理者は入れない。パスワードの付け直しは
  `docs/OPERATIONS.md` の「管理者がパスワードを忘れてサインインできないとき」と同じ手順で行う。
- 派生のアプリが `APP_ENV` を `production` 以外の名前で本番に出すと、この守りは効かない。
  deploy-repo の宣言の雛形（`deploy/k8s/20-config.yaml`）は `production` にしてある。
