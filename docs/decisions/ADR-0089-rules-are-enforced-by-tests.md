# ADR-0089: CLAUDE.md の規則は試験で止める

- 日付: 2026-10-30
- 状態: 承認

## 文脈

層の依存方向や設計の定量基準は CI で落ちる（ADR-0072 §1・§4）が、CLAUDE.md に書いてあるだけの規則も
多かった。持ち主の確認で棚卸しすると 13 の規則を何も止めておらず、時刻の生成口・スキーマの命名・ER 図は
実際にずれていた。全部の API に認可を付ける規則も止まっておらず、付け忘れると誰でも叩ける口ができる。
書くのも読むのも人と AI のエージェントで、読み落としは防げない。

## 決定

1. **機械で判定できる規則は、試験で止める。** 置き場は `tests/unit/test_coding_rules.py`（コードの書き方）・
   `tests/integration/api/test_route_authorization.py`（API の認可）・`tests/unit/test_documents_match.py` と
   `tests/integration/test_er_document.py`（文書と実物）。一覧は CLAUDE.md「品質ゲート」。
2. **例外は理由と一緒に試験の表へ書く。** 要らなくなった例外が残っていれば試験が落ちる。
3. **全部の API に主体の確かめを求める。** 公開する口は `(メソッド, 経路)` の一覧に理由と一緒に書く。
   `/api/admin`・`/api/system` は scope まで求める。`require_any_permission` は GET だけ。
4. **時刻の生成口を 2 つにする。** naive の `utcnow()` と tz 付きの `utcnow_aware()`。`datetime.now(UTC)` も直に書かない。
5. **`shared/kernel/version.py` は環境変数を直に読んでよい**（例外の表に書く）。`APP_ENV` は本番の判定に使うので、
   DB が環境変数より強い `settings`（ADR-0074 §1）を通すと画面や DB から変えられてしまう。
6. ruff・mypy・`requires-python` を、実際に動く Python 3.15 に揃える。
7. **判定には、規則を破った見本を見せて検出することを確かめる試験を付ける。** 「違反が 0 件」は、判定が何も見ていない
   ときにも成り立つ。経路の列挙は実際に 1 本も見つけないまま 3 本の試験を緑にした（FastAPI 0.162 は `include_router` した
   口を `app.routes` に並べない。`iter_route_contexts` の実効の値を読む）。

## 理由

- **試験にする（ruff のプラグインや別の道具にしない）**: 追加の依存が要らず、既存の `test_layer_dependencies.py` と同じ形で読める。
- **例外の表を試験の中に置く**: 例外の理由が判定のそばにあり、増やすには差分に理由を書くことになる。
- **認可は実物の経路から調べる（AST で読まない）**: `Depends` は `Annotated` や別名を通して付くので、組み立てた
  アプリの依存関係を辿るほうが確実。

| 採らなかった案 | 捨てた理由 |
|---|---|
| ルーターの既定を「認可あり」にする | 公開の口の書き方が特別になる。既存の口も全部書き換えになる |
| 文書を生成する | ER 図と画面仕様は説明も持つ（ADR-0072 §2）。食い違いの検出で足りる |
| 規則を減らして読む量を減らす | 規則そのものは要る。守らせ方の問題 |

## 影響

- 機械で止めていないものは CLAUDE.md に列挙した（ログの PII・試験の時刻と乱数・DI や命名の良し悪し）。レビューで見る。
- 派生アプリは取り込むと自分のずれが落ちる（CHANGELOG に手当てを書いた）。
- ⚠ OpenAPI のスキーマ名が変わる（`NotificationSchema` → `NotificationResponse` など）。画面は生成した型を使っていないので影響しない。
- Python 3.15 より古い環境ではもう動かない（`except A, B:` は 3.14 からの書き方）。
