# ADR-0055: サインインの往復で行き先（経路とクエリ）を落とさない

- 日付: 2026-10-21
- 状態: 承認

## 文脈

未サインインで認証必須の画面を開くと、`RequireAuth` がログイン画面へ送る。このとき行き先を
持たせずに `/login` へ送っていたため、SSO・パスワード・パスキーのどれで入っても着地（`/`）へ
戻された。サーバ側の SSO の入口（`GET /api/auth/sso/login?redirect_to=`）は行き先を受けて
往復の後に返す作りを持っていたが、画面が常に `/` を渡していた。

共有された深いリンク（`/items?q=…` のような経路とクエリ）を開いた人は、サインインした後に
もう一度その URL を開き直すしかない。派生アプリの blobshare は同じ不具合を ADR-0072 で
直していた。

## 決定

- `RequireAuth` はログイン画面へ送るとき、今の経路とクエリを `?redirect_to=` に載せる
  （着地から来たときは付けない）。
- ログイン画面はその値を絞って（`services/returnTo.ts`）、SSO の入口へ渡し、
  パスワード・パスキーで入ったときもそこへ遷移する。
- 絞る規則はサーバの `RedirectTarget.parse` と同じ（自サイト内の絶対パスだけ）。加えて
  サーバが受け取る上限の 255 文字を超えるものは着地へ倒す。

## 理由

- クエリ名はサーバの入口がすでに受けている `redirect_to` に揃えた。ログイン画面と入口で
  名前を変えると、読み替えの箇所が 1 つ増える。
- 長すぎる値をそのまま渡すと、入口が 422（JSON）を返して画面が止まる。行き先を失うほうが、
  サインインできないよりましである。
- 行き先は IdP の authorize には載せない（サーバ側の往復の記録に入る）。クエリに秘密を含む
  経路でも IdP へ持ち出さない。

## 影響

- 派生アプリは同じ 3 か所（`App.tsx` の `RequireAuth`、`LoginPage.tsx`、`services/returnTo.ts`）を
  取り込む。サーバ側の変更は無い。
- 古い版の画面を Service Worker が持っている端末では、新しい版に入れ替わるまで直らない。
