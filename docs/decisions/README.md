# 設計判断（ADR）の一覧

2026-10-30 に ADR-0001〜0070 を話題ごとに束ね直した（元の文面は git の履歴にある）。
参照は `ADR-0079 §1 決定 5` のように節（§）と項目まで書く。書き方は `CLAUDE.md`「設計判断」。

| ADR | 話題 | 節 |
|---|---|---|
| [ADR-0071](ADR-0071-database-and-data.md) | DB とデータの持ち方 | §1 本番は MariaDB、開発・テストは SQLite の二本立てにする<br>§2 DB のポートを外へ出さず、保守も DB のコンテナの中で行う |
| [ADR-0072](ADR-0072-development-workflow.md) | 開発の仕組み（品質ゲート・CI・文書） | §1 品質は CI の必須ゲートで守る（整形・静的解析・型・テスト）<br>§2 画面仕様・ER 図・ADR・Progress は変更と同じコミットで更新する<br>§3 CI は main への push と pull_request でだけ走らせ、古い実行は取り消す<br>§4 設計品質の定量基準を Ruff と AST テストで機械検証する<br>§5 Actions は Node 24 で動く版を使い、動く major タグが無いものだけ完全な版で固定する<br>§6 実ブラウザの E2E は煙試験に絞って雛形に置く |
| [ADR-0073](ADR-0073-build-and-deploy.md) | ビルド・配布と本番の守り | §1 デプロイ先は k3s、押す口は deck（build → pin → apply）<br>§2 アプリ自身の名前は `pyproject.toml` から導く<br>§3 SPA の受け皿は `/api/` を飲み込まない<br>§4 本番では、公開されている既定値（署名鍵・管理者のパスワード）で動かない<br>§5 守りのヘッダはアプリ自身が付ける |
| [ADR-0074](ADR-0074-settings.md) | 設定 | §1 画面で保存した設定は環境変数より強い<br>§2 起動時にしか読まれない設定は、DB 経由の再起動要求で反映する |
| [ADR-0075](ADR-0075-logs-and-audit.md) | ログと監査 | §1 監査ログを `audit_log` として分け、閲覧を audit コンテキストに集約する<br>§2 アプリログは失敗を中心に残し、記録の場所とレベルを 1 か所で決める<br>§3 ログの保持期間を設定キーで持ち、常駐スレッドで掃除する |
| [ADR-0076](ADR-0076-local-authentication-and-tokens.md) | ローカルの認証とトークン | §1 認証の基本の範囲<br>§2 二要素認証とパスキーは account_security コンテキストに置く<br>§3 認証の強度は入口ごとに決まる。ローカルの入口は丸ごと閉じられる<br>§4 トークンは httpOnly Cookie だけに置き、応答本文で配らない<br>§5 アクセストークンは DB を引かずに検証する（寿命 5 分）<br>§6 「ローカルのパスワードが無い」は NULL で表す<br>§7 この雛形はローカル口座を意図して持ち、入れる手段を数える<br>§8 パスワードを変えたら、それより前に始まったログインを終わらせる<br>§9 ログインの失敗を宛名ごとに数え、上限を超えたらしばらく断る<br>§10 パスキーの追加・削除とメールの変更は、入り直したばかりのときだけ |
| [ADR-0077](ADR-0077-sso-with-an-idp.md) | IdP（SSO）との連携 | §1 OIDC 認可コードフロー（PKCE）で入る<br>§2 サインアウトを IdP まで通すかはアプリが決める（既定は通さない）<br>§3 IdP で止めた利用者は、このアプリでも止まる（back-channel logout の受け口）<br>§4 同じメールアドレスの口座へ黙って寄せない（既定を無効にする）<br>§5 結び付けるのは入っている本人（設定画面から連携する）<br>§6 写しは IdP を正とする。メールアドレスは鍵ではない<br>§7 IdP で止まった人は、定期的に聞き直して SSO の入口だけ止める（定期照合）<br>§8 サインインの往復で行き先（経路とクエリ）を落とさない<br>§9 IdP で入っていれば、ログイン画面でボタンを押させない<br>§10 黙って断られた後でも、再読み込みしたらもう 1 回確かめる |
| [ADR-0078](ADR-0078-authorization-and-roles.md) | 認可とロール | §1 アクティブロールは JWT クレームで持ち、既定は全ロールの和集合<br>§2 ロール一覧の取得は `user:manage` でも許可する（変更は `role:manage` のまま）<br>§3 ロールを足す投入と、初期管理者を据える操作を分ける<br>§4 ロールは系統で分け、権限は自分の範囲でしか動かせない<br>§5 全権限のロールは `owner` と呼ぶ<br>§6 機能の権限はトークンで、資源 1 件ずつの可否は DB で確かめる |
| [ADR-0079](ADR-0079-tenants.md) | テナント | §1 テナントで人とデータを分け、システム管理者は中身を見ない<br>§2 テナントの絞りは表ごとに宣言し、リポジトリの入口で掛ける<br>§3 ロールはテナントの中に閉じ、システム管理者の席は別にする<br>§4 サインインはテナントの入口から始め、連携先はテナントの行が持つ<br>§5 テナント管理者は招待で指名し、システム管理者はパスワードを知らない |
| [ADR-0080](ADR-0080-screens.md) | 画面の作法 | §1 言語・テーマは「既定値はサーバー、選択はブラウザ」で持つ<br>§2 狭い画面への対応は CSS のブレークポイント 1 つとドロワーで行う<br>§3 個人設定はプロフィールに集め、メールアドレス・表示名は本人が直せる<br>§4 本人のアカウント設定はプロフィールとセキュリティの 2 画面に分ける<br>§5 サーバーへ問い合わせる操作は、押した直後にスピナーで実行中を示す<br>§6 入力はダイアログに出し、狭い画面では幅いっぱいのシートにする<br>§7 新しい版は知らせるだけで、入れ替えるのは利用者が押したとき<br>§8 サーバーに届かないことを、ログアウトとして扱わない<br>§9 画面の中のアプリの像は favicon.svg をそのまま使う<br>§10 前段が 503 で閉じていると答えたら、アプリ内のメンテナンス画面に切り替える |
| [ADR-0081](ADR-0081-mobile-app-and-notifications.md) | スマホアプリと通知 | §1 Android アプリは assay に直接ログインし、API は assay のアクセストークンを受け取る<br>§2 戻り先の案内ページは、認可コードが付いていれば「タップで開き直す」ボタンを出す<br>§3 お知らせは管理画面から送り、ベル・画面上部・端末への通知で届ける<br>§4 スマホアプリの最新版は、サーバーが配布面の latest.json を読んで返す<br>§5 スマホアプリへの通知は FCM（HTTP v1）で送り、鍵はファイルの場所で持つ |
| [ADR-0082](ADR-0082-machine-clients.md) | 機械の口 | §1 機械の口をテンプレートに入れる基準と、外せない検証<br>§2 機械に何をしてよいかは、idp ではなくアプリの許可簿で決める |
| [ADR-0083](ADR-0083-outbound-destinations.md) | 利用者が渡した宛先 | 利用者が渡した宛先へは、確かめてからつなぐ（Web Push は通知サービスのホストだけ） |
| [ADR-0084](ADR-0084-actors-and-roles.md) | アクターとロール | §1 アクター<br>§2 ユースケースと担当<br>§3 権限は「対象:操作」で、見ると変えるを分ける（設定はシステムとコンテンツの 2 層）<br>§4 ロール（サポート担当・コンテンツ管理者を足す） |
| [ADR-0085](ADR-0085-content-settings.md) | コンテンツ設定 | 定義をコードに、テナントが変えた値だけを DB に持つ（`content_settings`・`/api/admin/content-settings`） |
| [ADR-0086](ADR-0086-ci-runs-on-forge-without-github.md) | CI の台と取り寄せ先 | CI は forge の自前の台で動き、GitHub から何も取らない（ADR-0072 §5 を置き換え。uv は版を書かず写しの最新） |
| [ADR-0087](ADR-0087-machine-entrance-and-allowlist.md) | 機械の口と許可簿 | 機械の口（`POST /api/machine/token`）は許可簿の操作（権限コード）だけを scope に載せ、scope で守った口だけを通す |
| [ADR-0088](ADR-0088-no-task-list-in-the-repository.md) | タスクの一覧 | タスクの一覧（`Progress.md`）をリポジトリに置かない（ADR-0072 §2 のタスク管理を置き換え） |
| [ADR-0089](ADR-0089-rules-are-enforced-by-tests.md) | 規則を機械で止める | CLAUDE.md の規則は試験で止める。例外は理由と一緒に試験の表へ。全部の API に認可を求め、公開する口は一覧にする |
| [ADR-0090](ADR-0090-outbound-settings-are-env-only.md) | 通信先の設定 | 通信先の URL と鍵のファイルの場所は環境変数だけ（画面は見るだけ）。メールサーバーとテナントの発行者は形を確かめて受け取る |
| [ADR-0091](ADR-0091-refresh-sessions.md) | ログインの控え | ログインごとの控えを持ち、ログアウトで終わらせ、リフレッシュトークンを振り替えて使い回しを断る（ADR-0076 §8 の「ログアウトは Cookie を消すだけ」を置き換え） |
| [ADR-0092](ADR-0092-refresh-rotation-interval.md) | 振り替えの間隔 | リフレッシュトークンは猶予（30 秒）に 1 回だけ振り替える。複数のタブの更新を使い回しに見せない（ADR-0091 決定 3 を置き換え） |
| [ADR-0093](ADR-0093-require-two-factor-for-password-sign-in.md) | 二要素の必須化 | パスワードで入る人に二要素認証を必須にする設定をアプリ全体に 1 つ持つ。未登録のログインは登録の口しか通さない |
| [ADR-0094](ADR-0094-profile-is-owned-by-the-idp.md) | 名前とメールの正 | IdP と結び付いている利用者の名前とメールは、IdP でだけ直す（画面と `PUT /api/auth/me` で断る。ADR-0080 §3 決定 2 を置き換え） |
| [ADR-0095](ADR-0095-list-api-paging.md) | 一覧 API | `limit`・`offset` で受け、`entries`・`total` で返す。上限を超える指定は 422。見本は `/api/items` |
| [ADR-0096](ADR-0096-public-info-endpoint.md) | 未認証の `/info` | 残して版（`version`・`git_sha`）だけを返す。読み手の一覧は ADR にある |
| [ADR-0097](ADR-0097-purge-spent-password-tokens.md) | 再設定トークンの掃除 | 使えなくなったパスワード再設定トークンは、設定なしで 6 時間ごとに消す |
| [ADR-0099](ADR-0099-rename-script.md) | 名前の付け替え | 雛形の名前の付け替えは `scripts/rename_project.sh` の 1 行で行う。履歴と決定の記録は変えない |
