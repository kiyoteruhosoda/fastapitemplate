# ADR-0088: タスクの一覧をリポジトリに置かない

- 日付: 2026-10-30
- 状態: 承認
- 置き換える節: ADR-0072 §2 の「タスク管理」（`Progress.md` を唯一のタスク一覧にする）

## 文脈

ADR-0072 §2 は `docs/Progress.md` を唯一のタスク一覧とし、着手前に行を足し、完了時に消すことを
CLAUDE.md の義務にしていた。実際のタスクはリポジトリの外の課題管理（task.nolumia.com）で持つように
なり、`Progress.md` は更新されないまま済んだタスクが残っていた（2026-10-30 に 4 件が済んだまま載っていた）。
派生アプリにも同じ一覧と義務が写され、雛形の残タスクが派生アプリのものに見えた。

## 決定

1. `docs/Progress.md` を消し、タスクの一覧をリポジトリに置かない。
2. CLAUDE.md から、`Progress.md` を開く・行を足す・状態を進める・完了時に消すという義務を外す。
3. 完了した重要な変更は今までどおり `docs/CHANGELOG.md` に要約を書く。

## 理由

- 一覧が 2 か所にあると、片方は必ず古くなる。古いほうを読んだ人は、済んだものを未着手と取り違える。
- 雛形のタスクは雛形のもので、派生アプリへ写ると誤解を生む。

| 採らなかった案 | 捨てた理由 |
|---|---|
| `Progress.md` を残し、課題管理と手で揃える | 揃える作業が続かなかった（今回の食い違いがそれ） |
| 課題管理から `Progress.md` を自動で書き出す | 書き出した一覧を読む人が居ない。課題管理を直接見れば足りる |

## 影響

- 消した時点の残タスク（`SECRET_KEY` の整理・ログアウトでの失効・ローカルログインへの多要素の強制・IdP で入る
  利用者の名前とメールの編集・一覧 API のページング・`/metrics` と `/info` の露出・依存の脆弱性検査・
  リセットトークンの掃除・`example` の見本・名前の付け替えスクリプト）は、git の履歴（この ADR を足したコミットの
  1 つ前の `docs/Progress.md`）で読める。続けるものは課題管理に起こす。
- ADR の本文で「`Progress.md` の Tn」と書いていた箇所は「未対応」に読み替えた。
