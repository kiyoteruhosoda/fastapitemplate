# ADR-0041: アクセストークンは DB を引かずに検証する（寿命 5 分）

- 日付: 2026-09-15
- 状態: 承認

## 文脈

アクセストークンを検証するたびに DB を引いていた。1 リクエストあたり

- `users` の 1 件引き（`is_active` を見る）
- **ロールと権限の遅延読み込み**（ロール 1 つにつきさらに 1 本）
- 失効の記録の照会（ADR-0036。SSO で始まったセッションのとき）

が走る。認証済みの全リクエストに掛かるので、**アプリのいちばん内側で最も多く走る
クエリ**になっていた。

この形には見返りもあった。**止めた瞬間から次の 1 リクエストで効く**——ローカルの
無効化も、IdP からの停止（ADR-0036）も、ロールの取り上げ（ADR-0017）も。

## 決定

### 1. アクセストークンの検証は署名とクレームだけで行う

`TokenService.verify_access_token_with_reason` から `Session` を外した。判断材料は
`sub` / `email` / `username` / `scope` / `active_role` で、**すべてトークンに載っている**。
`get_current_principal` からも DB の依存を外した。

⚠ **`username` をアクセストークンへ足した。** 以前は principal の組み立てで DB から
取っていた。**検証が DB を引かない以上、principal の材料は全部クレームに載せる**——
載せ忘れた項目は、その経路でだけ静かに空になる。

### 2. 寿命を 5 分にする（既定 900 → 300 秒）

⚠ **この値が「止めたら効くまで」の上限時間そのものになる。** 長くするほど、停止も
権限の取り上げも遅れて効く。

### 3. ⚠ 止める判定は**更新の 1 点**に集約する

`verify_refresh_token` は DB を引き続ける（`is_active` と失効の記録）。

**ここが引き締めているから、アクセス側を緩められる。** 止められた利用者は
**新しいアクセストークンを受け取れない**ので、通り続けられるのは手元の 1 枚が
切れるまでになる。⚠ **ここを緩めると、寿命による上限そのものが消える。**

### 4. 利用者の行が要る経路は今までどおり引く

`get_current_user` は 1 件引く。⚠ **これは認可の判定ではない**——行そのものを
使う経路（プロフィールの更新、連携の状態など）が自分の都合で引いているだけである。

## 理由

**認可に要る値は、発行の時点で確定している。** 毎回引き直していたのは「発行してから
状況が変わったかもしれない」ためだが、その心配は**更新のたびに確かめれば足りる**。
確かめる回数をリクエストごとから 5 分ごとへ落としても、**分かるのが遅れる上限は
5 分**にしかならない。

これは OAuth 2.0 / OpenID Connect が前提にしている形でもあり、idp の ADR-0049 I7 が
「アクセストークンを短命にする（**受け口が落ちていたときの上限時間になる**）」と
書いているのは、まさにこの構えを指している。⚠ **これまでは毎回引いていたので、
その一文はこのアプリには当てはまっていなかった。** 今回から当てはまる。

### 検討して捨てた案

- **短い TTL のプロセス内キャッシュ**（数秒）。DB の往復はほぼ消え、即時性もほぼ
  保てる。⚠ **ワーカーごとに別のキャッシュを持つ**ので「いつ効くか」が ワーカーの数だけ
  ばらつき、**説明できない遅れ**が残る。5 分と言い切れるほうが運用しやすい。
- **失効だけを 1 本の軽いクエリにする**（ロールと権限はトークンから読む）。
  クエリ数は 3〜4 本から 1 本へ減るが、**リクエストごとに DB を引くこと自体は残る**。
  減らしたいのはそこだった。
- **Redis などの共有キャッシュを挟む。** 引く先が変わるだけで、往復は残る。
  依存も 1 つ増える（この雛形は Redis を前提にしていない）。

## 影響

- ⚠ **停止が効くまで最大 5 分かかる。** ローカルの無効化も、IdP からの停止も同じ。
  `test_the_access_token_outlives_the_stop_only_until_it_expires` が**この緩さを
  明示的に固定している**（消すと、緩んだことに誰も気付けなくなる）。
- ⚠ **ADR-0017 の「切り替えた後に外されたロールの権限を無効化する」も 5 分遅れる。**
  発行の時点で積集合を取るのは変わらないが、**発行済みのトークンは切り詰められない**。
- **更新の回数が 3 倍になる**（15 分 → 5 分）。DB の仕事は消えるのではなく更新へ移る。
  移った先は 5 分に 1 回で、リクエストごとではない。
- `verify_access_token_with_reason` の引数から `session` が消えた（呼び出し 2 か所）。
- ⚠ **この上限を縮めたいときに触るのは `ACCESS_TOKEN_EXPIRES_SECONDS` である。**
  管理画面の項目にもその旨を書いた。
