# ADR-0016: 個人設定はプロフィールページへ集約し、メールアドレス・表示名は本人が変更できる

- 日付: 2026-08-01
- 状態: 承認

## 文脈

言語・テーマの切り替えはヘッダー（狭い画面ではドロワーの下端）に常設されていたが、
毎回使う操作ではなく、ヘッダーの幅を圧迫していた（狭い画面で 3 段に折り返す問題の
遠因。ADR-0011）。また、メールアドレス・表示名の変更は `user:manage` を持つ管理者に
依頼するしかなく、本人が自分のアカウント情報を直せなかった。

サイドバーの階層化（「管理」「システム管理」のグループ化）に合わせて、
「個人の設定をどこに置くか」「本人にどこまで変更を許すか」を決める必要があった。

## 決定

- 言語・テーマの選択はプロフィールページ（`/profile`）の「表示設定」に移す。
  ヘッダー・ドロワーからは撤去する。保存先はブラウザのまま（ADR-0005 は変えない）。
- メールアドレス・表示名は本人が `PUT /api/auth/me` で変更できる。
  変更は監査ログへ `profile.updated` として残し、`reason` には変更した項目名だけを
  入れる（値そのものは記録しない。ADR-0013）。
- パスワード変更（要現在パスワード）・二要素認証・パスキーは従来どおり別画面
  （`/change-password`・`/security`）のまま。プロフィールからのリンクで辿る。

## 理由

- **プロフィールへの集約**: 「自分に関する設定」の置き場所が 1 か所になり、
  ヘッダーは常時使う操作（ナビゲーション・ログアウト）だけになる。
  ドロワー下端の特例配置（ADR-0011 の補足）も不要になる。
- **本人による変更を許す**: 表示名・メールアドレスは本人のものであり、管理者を
  経由させる運用は小規模チームでは手間に見合わない。一意性（メールアドレス）は
  サーバー側で検証し、重複時は `email_already_exists` を返す。
- **メールアドレス変更に再確認メールを挟まない**: テンプレートの既定ではメール送信が
  無効（`MAIL_ENABLED=off`）で、確認メール方式は成立しない。認証済みセッション＋
  監査ログで追跡可能とし、確認フローが必要なプロジェクトは拡張点として足す。
- **パスワードと分ける**: パスワード変更は現在パスワードの再入力を要求する
  「重い」操作で、再入力なしで済むプロフィール編集と同じフォームに混ぜると
  どちらかの UX が崩れる。

## 影響

- JWT は `sub`（ユーザー ID）でユーザーを引き直すため、メールアドレスを変えても
  発行済みトークンはそのまま有効（再ログイン不要）。次回ログインから新しい
  メールアドレスを使う。
- 未認証画面（ログイン等）には言語・テーマの切り替えが無い。既定値
  （`DEFAULT_LOCALE` / `DEFAULT_THEME`）と保存済みの選択で描画される。
- なりすまし対策として確認メールを要するプロジェクトは、`PUT /api/auth/me` の
  メール変更部分をトークン確認方式へ差し替える必要がある。
