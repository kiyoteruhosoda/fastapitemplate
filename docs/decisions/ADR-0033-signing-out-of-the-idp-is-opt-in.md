# ADR-0033: サインアウトを IdP まで通すかはアプリが決める（既定は通さない）

- 日付: 2026-09-07
- 状態: 承認

## 文脈

`POST /api/auth/logout` はこのアプリのセッションを終わらせる。**IdP の SSO
セッションには触れない。**そのため SSO でログインした利用者がサインアウトしたあと
「SSO で入る」を押すと、**名乗り直さずに入れる**。

自前 idp (assay) を使う別のアプリ（SSO 専用で利用者表を持たない操作盤）では、これが
「サインアウトしてもサインアウトされない」という形で表に出た。そちらは
OIDC RP-Initiated Logout 1.0 の `end_session_endpoint` へ送り出して直した。

同じ手当てをこの雛形にも入れるかを検討したが、**素直に入れると副作用がある。**

`end_session_endpoint` が消すのは **IdP の SSO セッション 1 つ**で、これは
**その IdP を使う全アプリで共有されている**。つまり片方のアプリのサインアウトが、
もう片方の**次回 SSO ログイン**に効く。他アプリの既存セッションは切れない——
あれは各アプリ自身の Cookie で、IdP が知らせるのは `backchannel_logout_uri` を
登録したクライアントにだけだからである。それでも、**利用者が頼んでいない他アプリへの
副作用**であることは変わらない。

## 決定

**機能は用意する。既定は無効。** `OIDC_RP_LOGOUT_ENABLED`（真偽値、既定 `false`）。

- 無効のとき、振る舞いは**これまでと 1 か所も変わらない**（画面は遷移しない）。
- 有効のときだけ、画面はアプリのサインアウトを終えてから
  `GET /api/auth/sso/logout` へ遷移し、そこが IdP へ送り出す。
- 戻り先は `GET /api/auth/sso/signed-out`。`OIDC_POST_LOGOUT_REDIRECT_URI` が
  空なら `APP_BASE_URL` から組み立てる（`OIDC_REDIRECT_URI` と同じ作法）。
- **通せない場面は失敗にしない。** 設定が無効・SSO が使えない・IdP が
  `end_session_endpoint` を出していない・discovery が引けない——どれもログイン画面へ
  返すだけにする。

## 理由

**ローカル口座を持つアプリでは、既定を無効にするのが正しい。** `POST /logout` は
既に自分のセッションを終わらせている。そこへ他アプリへの副作用を足す理由が無い。

**有効にする価値があるのは 2 つの形。**

1. **SSO でしか入れないアプリ**（`LOCAL_LOGIN_ENABLED=false`）。IdP のセッションが
   唯一のセッションなので、通さないとサインアウトが成立しない。
2. **共有の端末で開くもの。** サインアウトした画面からボタン 1 つで入り直せると困る。

**`id_token_hint` は送らない。** この雛形は検証したあとの ID トークンを保持しない
（手元に無いものは送れない）。代わりに `client_id` + `post_logout_redirect_uri` の
組で名乗る。OP はこの組で登録済みかを見る。保持するなら行を 1 本増やす話になるので、
必要になったアプリで別途決める。

**判断材料は `GET /api/auth/me` が返す**（`rp_logout_enabled`）。画面が設定を
焼き込むと、設定を変えたあと焼き直すまで食い違う。`GET /api/auth/sso/provider` でも
返しているが、あちらは**ログイン画面**のためのもの。ログイン済みの画面がそれを引くと、
**サインアウトの経路に往復が 1 つ増える**（しかも SSO を使わない構成でも毎回）。
`/me` は起動時に必ず引くので、載せるぶんには増えない。

⚠ **`/me` が返すのは設定であって、この画面がどう入ったかではない。** パスワードで
入った利用者がサインアウトしても IdP のセッションを落とす。真にするのは
「SSO でしか入れないアプリ」と「共有の端末で開くもの」だけなので、前者に
パスワード利用者は居らず、後者では**落とすほうが望ましい**。ローカル口座を持つ
アプリで真にしないこと、という上の線引きがそのままこの前提でもある。

**`GET /api/auth/sso/logout` は同一サイトからの遷移だけ通す**（`Sec-Fetch-Site`）。
この口は**未認証で状態を変え**、しかも変えるのは全アプリで共有された SSO セッション。
守らないと、よその頁が `<img src="…/api/auth/sso/logout">` を置くだけで
**利用者を他アプリからも締め出せる**。

⚠ **IdP の確認画面をあてにしない。** OIDC は `id_token_hint` が無いとき OP が確認を
挟むことを *SHOULD* としているだけで、**自前 idp (assay) は挟まない**（実装を確認済み）。
CSRF トークンではなく `Sec-Fetch-Site` を見るのは、ここが**画面遷移**だから——
トークンを載せるには JavaScript で URL を組むことになり、`<a href>` で開けるという
性質を捨てることになる。**ヘッダーごと無い場合は通す**（付けないのは古いブラウザで、
よその頁から起こした遷移では今のブラウザが必ず付ける）。

## 結果

- ⚠ **有効にしたら `post_logout_redirect_uri` を IdP へ登録すること。**
  未登録でも壊れはせず、**IdP 自身の完了ページで止まる**（エラーにならないので、
  登録漏れは「戻ってこない」という形でしか出ない）。
- 「このアプリだけ毎回名乗り直させたい」だけなら、こちらではなく認可要求の
  `prompt=login` のほうが副作用が無い。**両者は別の道具**として使い分ける。
- 単一ログアウト（片方のサインアウトで全アプリのセッションを落とす）は**別の話**で、
  `backchannel_logout_uri` の登録と受け口が要る。ここでは扱わない。
- IdP から戻った印の `?signed_out=1` は、ログイン画面が `login.signedOut` で出す。
  **出さないと、期限切れで飛ばされたのと見分けが付かない。**
