# ADR-0101: リフレッシュトークンの寿命を更新で延ばすかを設定で選ぶ

- 日付: 2026-11-02
- 状態: 承認（影響の「IdP からの停止を覚えておく長さ」は ADR-0102 で置き換え）
- 関係: ADR-0091（控えと振り替え）・ADR-0092（猶予に 1 回だけ振り替える）はそのまま。ADR-0091 決定 7 の「パスワードの変更は新しい行を作る」も変えず、寿命だけを受け継ぐ

## 文脈

期間は `REFRESH_TOKEN_EXPIRES_SECONDS` で変えられるが、延長は変えられない。更新で振り替えるたびに `expires_at`・`exp`・Cookie の `max_age` が今から期間ぶん先へ延びるので、使い続ける限りログインは終わらない。ログインからの長さに上限を置きたいアプリでは、それを選べない（task #827）。

## 決定

1. **真偽値の設定 `REFRESH_TOKEN_SLIDING_ENABLED` を足す。既定は真**（今の動きを変えない）。
2. **偽のときの寿命はログインから数える。** 振り替えは続ける（ADR-0091 決定 2）。`expires_at`・リフレッシュの `exp`・`logout_token` の `exp`・両方の Cookie の `max_age` を 1 つの値から揃える。
3. **偽のとき、振り替えの `UPDATE` は `expires_at` を書かない。** 勝ち負けの条件（ADR-0091 決定 4・ADR-0092 決定 2）と `SET` の順番は変えない。寿命を読むのは `UPDATE` の前の 1 回だけで、勝ち負けの判定には使わない。
4. **設定を変えて効くのは次の更新から。** 偽へ変えても今の `expires_at` は縮めない（期間を短くしても同じ）。真へ戻すと次の振り替えから延びる。
5. **控えを引き継ぐ経路も同じ規則に従う。** ロールの切り替えは同じ行を振り替え、パスワードの変更は新しい行へ寿命を受け継ぐ。
6. **`expires_at` を過ぎたログインは、出し直しの口でも終わっている**（`_session_revoked`）。期間は 1 秒以上 10 年以下だけを保存でき、環境変数や保存済みの値がその外なら既定へ戻す。

## 理由

- **`UPDATE` で書かない（読んだ値を書き戻さない）**: 「延長なしでは更新で変わらない」を読み書きの順番に頼らず、SQL の形で保証できる。
- **決定 6 の期限の確認**: アクセストークンは期限の後も最大で寿命（既定 5 分）生きる。確かめないと、ロールの切り替えを繰り返すだけで出し直しが続き、上限が無くなる。
- **秒に揃える**: `exp` は秒までで、MariaDB の `DATETIME` も秒まで。先に秒へ落とせば、どの DB でも同じ値になる。
- **上限 10 年**: 桁を間違えた値は日時の計算であふれ、ログインが全部 500 になる。

| 採らなかった案 | 捨てた理由 |
|---|---|
| 振り替えのオン・オフも足す | 使い回しの検出が弱まる（ADR-0091） |
| `users` に列を足して寿命を持つ | 読むのは控えの行で足りる。`users` は移行 0002 の都合で増やせない |
| 偽へ変えた時点で `expires_at` をログインからの長さへ縮める | 設定を変えただけで今のログインが切れる |
| ログインの時刻（`created_at`）＋今の期間で毎回計算する | 期間を短くすると今のログインが縮み、切れる |
| アクセストークンの `exp` も期限で切り詰める | 短くなるのは最大で既定 5 分の幅だけで、`exp` を揃える対象を増やすほどの益が無い |

## 影響

- 延長なしでも、期限の後に手元のアクセストークンは寿命まで通る（ADR-0076 §5 と同じ緩さ）。出し直しと更新はできない。
- `csrf_token` の Cookie の寿命は今までどおり設定の期間のまま。秘密ではなく、期限の後に残っても何もできない。
- 期間を短くしても、延長なしの今のログインは元の期限まで続く。IdP からの停止を覚えておく長さ（`keep_for_seconds`）は今の期間に従う。
- ⚠ 派生アプリには取り込んでいない。取り込むときは `create_token_pair` の `refresh_expires_at` と `establish_session` を一緒に入れる。
