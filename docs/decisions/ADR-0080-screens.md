# ADR-0080: 画面の作法

- 日付: 2026-10-30
- 状態: 承認（§6 の縦組みの見出しの高さ 10.5rem は ADR-0084 で 11rem に置き換え）
- 統合した ADR: 旧 ADR-0005（§1）・旧 ADR-0011（§2）・旧 ADR-0016（§3）・旧 ADR-0020（§4）・旧 ADR-0022（§5）・旧 ADR-0027（§6）・旧 ADR-0035（§7）・旧 ADR-0050（§8）・旧 ADR-0053（§9）・旧 ADR-0067（§10）（2026-10-30 に統合。元の文面は git の履歴にある）

## 文脈

フロントエンドは SPA（React + Vite）で、Service Worker を持つ PWA である（`vite-plugin-pwa`）。
この雛形から作るアプリは画面を作り替えるので、ここで決めるのは「どの画面でも同じに振る舞うべきこと」
——表示の好み、狭い画面への対応、入力の出し方、押した操作の手応え、版の入れ替え、サーバーに
届かないときの見せ方——である。共通の前提は 2 つある。

- **画面幅の判定は CSS が持つ。** コンポーネントは「開いているか」だけを状態として持つ（§2・§6）。
- **jsdom は CSS・`<dialog>`・Service Worker を実装しない。** 単体試験で見られるのは状態の遷移まで。
  実ブラウザでしか分からないものは `frontend/e2e/` の煙試験（ADR-0072 §6）で見る。

## 決定

### §1 言語・テーマは「既定値はサーバー、選択はブラウザ」で持つ

API はエラーコードを返し、翻訳はフロントエンドが行う（CLAUDE.md「国際化」）。

1. 表示文言の翻訳はフロントエンドの JSON 辞書で行う。サーバー側 gettext は入れない。
2. 既定値と選択肢（`LANGUAGES` / `DEFAULT_LOCALE` / `DEFAULT_THEME`）は公開エンドポイント
   `GET /api/ui/settings` で配る（認証は要求しない）。
3. 利用者の選択は `localStorage` に保存する。優先順位は
   「利用者の選択 > ブラウザの言語（言語のみ）> サーバーの既定値」。
4. テーマは `light` / `dark` / `system` の 3 値。`system` は OS の設定に追従し、`matchMedia` の変化も
   購読する。配色は CSS 変数で持ち、`<html data-theme>` で切り替える。
5. 選択の部品（`PreferenceControls`）はプロフィールの「表示設定」区画にだけ置く（§3）。

### §2 狭い画面への対応は CSS のブレークポイント 1 つとドロワーで行う

1. **CSS のメディアクエリ 1 つ（`max-width: 48rem` = 768px）で切り替える。**
   コンポーネントは画面幅を判定しない。
2. 狭い画面ではサイドバーを画面外へ退避させ、ヘッダーのボタン（☰）で開閉するドロワーにする。
   開閉状態は `components/AppLayout.tsx` が持ち、`nav[data-open]` 属性として CSS へ渡す。
   ドロワーはヘッダーごと覆い、閉じるボタンをドロワー内に置く。
3. 表は `<div className="table-scroll">` で包み、**表だけ**が横スクロールする
   （狭い画面では表の下限を `min-width: 34rem` にする）。列を落とす・カード表示に変えることはしない。
4. 狭い画面では入力欄・ボタンの最小高さを 2.75rem、文字を 16px にする（iOS Safari の自動拡大を防ぐ）。
   チェックボックスは枠ではなく目盛りそのものを 1.5rem にする。

### §3 個人設定はプロフィールに集め、メールアドレス・表示名は本人が直せる

1. 言語・テーマの選択はプロフィール（`/profile`）の「表示設定」に置く。ヘッダー・ドロワーには置かない。
   保存先はブラウザのまま（§1）。
2. メールアドレス・表示名は本人が `PUT /api/auth/me` で変更できる。メールアドレスの一意性は
   サーバーが確かめ、重複なら `email_already_exists` を返す。確認メールは挟まない。
3. 変更は監査ログへ `profile.updated` として残し、`reason` には変更した項目名だけを入れる
   （値そのものは記録しない。ADR-0075 §1）。
4. パスワード・二要素認証・パスキーはセキュリティ画面に置く（§4）。

### §4 本人のアカウント設定はプロフィールとセキュリティの 2 画面に分ける

**関心ごとに 2 画面へ分け、親子（プロフィール → セキュリティ）にする。**

| 画面 | ルート | 区画 |
|---|---|---|
| プロフィール | `/profile` | アカウント、セキュリティ（入口）、表示設定、ロール、有効なスコープ |
| セキュリティ | `/profile/security` | パスワード変更、二要素認証、パスキー |

1. パスワード変更は独立した画面にせず、セキュリティの区画にする。パスワード・二要素認証・パスキーは
   どれも「どうやってサインインするか」という 1 つの関心である。
2. 入口はヘッダーのユーザー名 → プロフィールの「セキュリティ」区画（見出し・説明・リンク）だけ。
   セキュリティ画面からはプロフィールへ戻るリンクを置く。サイドバーには出さない。
3. 旧 URL（`/change-password`・`/security`）は `/profile/security` へ転送する（`App.tsx`）。
4. 区画の中身は再利用できる部品にする（`components/PasswordChangeForm.tsx`・`TwoFactorControls.tsx`・
   `PasskeyControls.tsx`・`PreferenceControls.tsx`）。区画の見出しと枠は呼び出し側の画面が持つ。
   区画の CSS クラスは 2 画面で共有する `.settings-section` / `.settings-form`。

### §5 サーバーへ問い合わせる操作は、押した直後にスピナーで実行中を示す

1. サーバーへ問い合わせるボタンは `components/ActionButton.tsx` を使い、実行中はスピナーを出して
   押せなくする。素の `<button>` は画面内で完結する操作（表示の切り替え・入力の消去・メニューの開閉）に限る。
2. 実行中かどうかは `hooks/usePendingAction.ts`（単発の操作）と `hooks/usePendingRows.ts`（一覧の行ごと）が
   持つ。フックは `ref` で判定し、実行中の再呼び出しを無視する（二重送信の防止）。
3. スピナーはラベルの上に重ね、ラベルは場所を占めたまま隠す（ボタンの幅を変えない）。
4. 目印を出すのは**押された操作だけ**。実行中の状態は真偽値ではなく「どれを実行中か」で持つ。
   誰も押していない初回の読み込みでは、どのボタンにも目印を出さない。
5. 検索・ページ送りのように表の中身が入れ替わる操作も対象。ログ画面は `hooks/useLogSearch.ts` が
   取得中かを返し、画面側がどの操作（検索・クリア・失敗だけ・前へ・次へ）が取得を起こしたかを保つ。
6. `aria-busy` に加えて、読み上げ用の文言（`common.processing`）を視覚外に置く。
7. 目印の見た目は `src/index.css` の `.spinner` が唯一の出所。`prefers-reduced-motion` では止めずに遅くする。

### §6 入力はダイアログに出し、狭い画面では幅いっぱいのシートにする

一覧の画面で、たまに使う追加フォームやログの絞り込みが先に来て、390px 幅では一覧の 1 件目まで
350〜1,300px のスクロールが要った。権限・ロールの対応表は 1920px でも横に収まらなかった。
**入力の面を 3 つの形に分ける。**

1. **追加（作成）フォームは `<dialog>` に出す。** 画面には「追加」ボタンだけを置き、一覧を先頭に出す。
   狭い画面では画面の下から**幅いっぱい**のシート、広い画面では中央のダイアログとして開く。
   共通部品は `components/FormDialog.tsx`（`showModal()` を使い、モーダルを自前で組まない）。
2. **ログの絞り込みは畳めるようにする。** 狭い画面では既定で畳み、「絞り込み」で開く。広い画面では
   開閉ボタンごと消して常に見せる。開閉する区画（`aria-expanded` + `aria-controls`）として作り、
   モーダルにはしない。共通部品は `components/FilterPanel.tsx`。
3. **対応表は列見出しを縦組みにし、行の見出しを左端に固定する**（`.matrix`）。カードの幅の上限も外す。

どの形で出すかは `index.css` が決める（§2 決定 1）。

### §7 新しい版は知らせるだけで、入れ替えるのは利用者が押したとき

SPA は画面を描き替えるだけでページを読み込み直さないので、デプロイしても開きっぱなしの画面
（特にインストールした PWA）は古い版のまま動き続ける。

1. `vite-plugin-pwa` を `registerType: 'prompt'` にし、待機している版があるときだけ
   「新しい版があります [再読み込み]」を画面の下に出す。**押されるまで消さない**（数秒で消えるトーストは使わない）。
2. 押すと、待機している Service Worker に `SKIP_WAITING` を送り、制御が移ったら（`controllerchange`）再読み込みする。
3. ⚠ **合図が来ない場合の逃げ道を持つ。** 画面をまだ Service Worker が制御していない（登録直後の初回訪問）と
   `controllerchange` が起きない。2 秒待って、こちらからも読み直す。
4. **更新の確認を自分で起こす。** SPA の画面切り替えはページ遷移ではないので、ブラウザは確認しに行かない。
   30 分ごとと、タブが手前へ戻ったときに確認する（オフライン・取得中・直前に確認済みなら起こさない）。
5. サーバーは `index.html` と `sw.js` に `no-cache` を付け、ハッシュ付きの `assets/` だけを長期キャッシュにする
   （`presentation/fastapi/routers/spa.py`）。

### §8 サーバーに届かないことを、ログアウトとして扱わない

リリースのあいだアプリは 1〜2 分応答しない（edge が 503 を返す）。殻は Service Worker が出すので開けるが、
API は届かない。失敗を未ログインと読むと、パスワードの入口を閉じたアプリで「ログイン画面に SSO のリンクが
無い」まま取り残される（派生の toeic で起きた）。

1. `/api/auth/me` が **4xx なら未ログイン**、**5xx・通信の失敗なら「届かない」**として分ける。届かないときは
   ログイン画面へ送らず「サーバーにつながりません（新しい版を配っている最中かもしれません）」を出し、
   5 秒ごとに聞き直す（`store/AuthContext.tsx` の `unreachable`・`RECONNECT_INTERVAL_MS`）。
2. ログイン画面は、入口の問い合わせ（`/api/auth/sso/provider`）が**届くまでどの入口も出さない**。
   届かなければ同じ文言を出し、5 秒ごとに聞き直す。問い合わせに失敗したらローカルの入口を出したままにする、
   という扱いはしない（`frontend/README.md` S1）。
3. 前段がメンテナンス・停止と答えた 503 は §10 で別に扱う（その間はこの聞き直しを止める）。

### §9 画面の中のアプリの像は favicon.svg をそのまま使う

1. 画面の中の像は部品 `AppMark`（`frontend/src/components/AppMark.tsx`）に寄せ、絵は持たずに `favicon.svg` を
   `<img>` で読む。ヘッダーとサインイン前の画面（ログイン・パスワード再設定）に出す。
2. タブ・ホーム画面のアイコンと `favicon.svg` は `scripts/generate_pwa_icons.py` 1 本から作る。これが図柄の正本。

### §10 前段が 503 で閉じていると答えたら、アプリ内のメンテナンス画面に切り替える

公開名の前段（edge）は、計画メンテナンスの宣言があるホストへの要求すべてに 503 を返す（nolumiatask #653・#654・#663）。
ブラウザ（`Accept: text/html`）には edge のメンテナンス画面、それ以外（JS・CSS を含む）には JSON を返す:

```json
{"error":"service_unavailable","reason":"maintenance","until":"2026-10-28T19:30:00Z",
 "message":"<理由>","title":"<見出し>","body":"<本文>"}
```

上流（このアプリ）が居ないだけのときは `{"error":"service_unavailable","reason":"stopped","host":"…"}`。
`title`・`body` は #663 で足したので、古い edge は返さない。

⚠ **この画面は PWA なので、edge のメンテナンス画面は見えない。** 画面の移動も読み込み直しも、Service Worker が
手元の index.html を返す（`navigateFallback`）。

1. API の応答が 503 で、本文の**最上位**が `error: "service_unavailable"` かつ `reason` が `maintenance` / `stopped`
   なら「前段が閉じている」と読む（`frontend/src/services/maintenance.ts` の `outageFrom`）。アプリ自身のエラー
   （`{"detail": {"error": …}}`）とは形で見分ける。読むのは API の入口（`api.ts`）と、最初に読む画面の設定（`uiSettings.ts`）。
2. 閉じている間は、アプリの画面を**消さずに隠し**、別の React の root にメンテナンスの画面
   （`components/MaintenanceScreen.tsx`）を描く。見出し・本文は edge の文言、無ければ既定の文（`maintenance` は
   「メンテナンス中」、`stopped` は「停止中」。画面の言語で出す）。理由（`message`）と戻りの見込み
   （`until` を閲覧者の時間帯で）も出す。
3. 画面は 1 分ごと・タブが手前へ戻ったとき・「いま確かめる」を押したときに `GET /api/ui/settings` で確かめ直す。
   通ればアプリの画面へ戻す（読み込み直さない。認証は聞き直す）。ほかの API の答えが返ったときも戻す。
4. 閉じている間はエラーのトーストを出さない。ログインの聞き直し（5 秒ごと。§8）も止める。
5. 遅れて読み込む部品（動的 import の JS・CSS）が読めなかったとき（Vite の `vite:preloadError`）は、閉じているかを
   確かめ、閉じていれば同じ画面を出して、開いたら読み込み直す。ただの失敗なら何もしない（`preventDefault` しない。
   エラーは今までどおり投げられる）。

## 理由

### §1

- **gettext を入れない**: 訳がサーバーとフロントの 2 か所に分かれ、`.mo` の再生成も要る。API がエラーコードだけを返すなら訳出はフロント 1 か所で済む。
- **既定値だけサーバーから配る**: ログイン前の画面でも要る。`LANGUAGES` / `DEFAULT_LOCALE` が「並ぶだけで何も動かさない設定」でなくなる。
- **選択をサーバーに保存しない**: 表を足すほどの価値が無く、端末ごとに違ってよい設定でもある。
- **`system` を持つ**: OS に追随しないと、夜間に画面だけ白く光る。配色を CSS 変数にすれば、テーマの追加が `:root[data-theme=...]` 1 ブロックで済む。

### §2

- **判定の出所を 1 か所にする。** JS（`matchMedia`）にも閾値を持たせると CSS と二重管理になり、初回描画もちらつく。
- **ブレークポイントは 1 つ。** 画面は「サイドバー + カード + 表」の 1 パターンしかなく、段階を増やすほど確かめる幅が増える。
- **ドロワー**: 項目数が scope で増減し、タブやボトムナビゲーションでは収まらない。サイドバーの `ITEMS` をそのまま使える。
  ヘッダーの下から開く案は、ヘッダーの高さが折り返しで変わり `top` を固定できないので採らない。
- **表は横スクロールに任せる。** どの列を落とすかを表ごとに決めずに済む。
- UI ライブラリ（MUI 等）は入れない。雛形は好みのライブラリへ置き換える前提で、その自由を先に奪う。

### §3

- **プロフィールへの集約**: 置き場所が 1 か所になり、ヘッダーは常時使う操作（ナビゲーション・ログアウト）だけになる。
  言語・テーマをヘッダーに置くと 390px で 3 段に折り返していた。
- **本人による変更を許す**: 本人のもので、管理者を経由させるのは小規模チームでは手間に見合わない。
- **確認メールを挟まない**: 雛形の既定ではメール送信が無効（`MAIL_ENABLED=off`）。認証済みのセッションと監査ログで追える。
- **パスワードと分ける**: 現在のパスワードの再入力を求める重い操作で、混ぜるとどちらかの使い勝手が崩れる。

### §4

- **画面を分ける単位は「関心」であって「操作」ではない。** 変えたいもの（自分は誰か／どうサインインするか）で分ける。
- 採らなかった案: **1 画面に全部**（区画 7 つで狭い画面では何があるか分からない。一度作って確かめた）・
  **タブ**（ブックマーク・再読み込み・戻るを自分で面倒みる）・**サイドバーに足す**（サイドバーは scope で出し入れする
  業務メニューで、全員に出る本人設定を混ぜると規則が崩れる）。

### §5

- **責務を部品へ寄せる。** 画面ごとに `busy` を書くと書き忘れが混ざる。書き忘れは「素の `<button>`」として差分に現れる。
- **二重送信の防止を同じ場所に置く。** `disabled` は次の描画まで効かず、同じフレームの 2 つ目を止められない。
- **幅を変えない。** 押した直後に並びが動くと、次の操作を押し間違える。
- **押した操作にだけ出す。** どれが動いているか分からないと、待つか押し直すかを判断できない。
- 画面全体を覆うオーバーレイは、押した場所と目印が離れ、行ごとの操作を表せないので採らない。

### §6

- **狭い画面では幅いっぱいに使う。** 左右の余白は 1 行の文字数を減らすだけ。下端なら決定と取り消しが親指の届く位置に来る。
- **`<dialog>` + `showModal()` を使う。** フォーカスの閉じ込め・Esc・背後の不活性化・重ね順（top layer）がブラウザの実装で済み、
  ヘッダー（`position: sticky`）やドロワーとの重ね順・フォーカスの戻し先を画面ごとに間違えずに済む。
- **絞り込みはモーダルにしない。** `role="dialog"` や `aria-modal` は CSS で外せない。開閉する区画にしておけば、
  広い画面では開閉ボタンを `display: none` にするだけで「常に開いている区画」として正しい意味になる。
- **対応表は横スクロールのまま読めるようにする。** 行の見出しを固定し、列見出しを縦組みで 1 列 2.5rem 前後まで詰める。
  実測でロール管理の 11 列が 390px 幅で 2 列 → 4 列見え、1280px 幅では横スクロールが消えた。
- 採らなかった案:
  - **絞り込みも `<dialog>` に入れる** — 広い画面で条件を変えるたびに開くことになる。求められたのは狭い画面の改善で、広い画面を悪くする理由が無い。
  - **列見出しを省略形にする**（`admin:system-settings` → `sys-set`）— 画面の値と API・監査ログの値が食い違う。
  - **`<details>` / `<summary>` で畳む** — `open` 属性は CSS から操作できず、広い画面で常に開けない。

### §7

- **黙って入れ替えても画面は新しくならない。** ⚠ `autoUpdate` は新しい Service Worker を有効にするだけで、読み込み済みの
  JavaScript は古いまま。しかも古い資産がキャッシュから消え、遅れて読む部品の取りに行く先が無くなる。`prompt` なら
  押すまで古い画面は古いキャッシュで完結し、利用者の側で「押さなかった」と分かる。
- **入力中の画面を奪わない。** 自動で読み込み直すと、書いている途中の入力を消しうる。
- **確認を自分で起こさないと知らせは出ない**（閉じて開き直した人にだけ届く知らせになる）。

### §8

- サーバーに届かないとき、どの入口を出しても押せば失敗する。出した既定の欄がサーバーが戻ったあとまで残るのが害だった。
- 「全員が締め出される」心配は、届かない間に限れば当たらない（届けば入口は出る）。
- 未ログインの答え（401）は届いたサーバーが返すもので、5xx・通信の失敗とは見分けられる。

### §9

- 正本が生成スクリプト 1 本になり、図柄や色を変えると全部の場所がいっしょに変わる。派生（WBS）が画面に別の絵を
  書いていて、タブのアイコンと違って見えた。
- SVG なので 28px のヘッダーでも 44px の見出しでもそのまま縮められ、角丸と地の色も絵の側に入っている。
- 図柄を React の部品として書き、生成スクリプトがそれを読む案は、正本が TS と Python に割れるので採らない。

### §10

- **API の応答で切り替える。** 画面の移動は Service Worker が答えるので、edge の画面を見せる道は無い。Service Worker の中で
  差し替える案は、オフラインでも開く PWA の働きを崩し §7 とも絡むので採らない。
- **別の root に描き、アプリは隠すだけ。** 部品が欠けてアプリの木が落ちても出せ、戻ったとき入力の途中も位置もそのまま戻る。
- **確かめ直しは 1 分ごと。** 宣言は数分〜数十分の単位で、`Retry-After` は 300 秒。
- **部品の失敗は確かめてから決める。** `vite:preloadError` からは理由が分からず、決め付けるとふつうの失敗までメンテナンスに見せる。
- **文言は edge のものを優先する。** 何が起きているかを書けるのは宣言した人だけ。edge の画面は英語だけ（#653）なので、既定の文は画面の言語で出す。

## 影響

### §1

- 管理画面で `DEFAULT_LOCALE` / `DEFAULT_THEME` を変えても、既に選んだ利用者の画面は変わらない（`localStorage` が優先）。
- 描画前に `/api/ui/settings` を 1 回取得する。失敗しても既定値で描画を続ける（503 の閉店の答えなら §10）。
- 未認証画面（ログイン等）には言語・テーマの切り替えが無い。既定値と保存済みの選択で描画される。
- 管理画面の設定ラベルはサーバーが英語で返す。フロントは `config.field.<KEY>` を辞書から引き、無ければサーバーのラベルをそのまま出す。

### §2

- **表を新しく置くときは `.table-scroll` で包む。** 忘れると狭い画面でページ全体が横スクロールする（`frontend/README.md` の画面追加の手順）。
- ドロワーを閉じる手段は ✕ ボタン・オーバーレイのタップ・Esc・項目の選択の 4 つで、`AppLayout.test.tsx` で確かめる。
  オーバーレイは装飾なので `aria-hidden` とし、支援技術からは ✕ と Esc で閉じる。
- **キーボード操作のためにフォーカスを動かす。** 開いたらドロワー内の先頭（✕）へ移し、Tab / Shift+Tab をドロワー内で折り返し、
  閉じたらメニューボタンへ戻す。覆われて見えない要素へ Tab で届くと、見えないものを操作することになる。
- ⚠ `visibility` の遷移時間は 0 にする（開くときは即座、閉じるときは 0.2s 後）。`transition: visibility 0.2s` と書くと開いた直後は
  まだ `hidden` で、`focus()` が黙って無視される。jsdom では再現しない。このためフォーカス移動は描画後の 1 フレームを待つ。

### §3

- 利用者は `sub`（利用者 ID）で識別するので、メールアドレスを変えても発行済みトークンはそのまま有効（再ログイン不要）。次回ログインから新しいメールアドレスを使う。
- ⚠ **IdP で入る利用者が名前・メールを直しても、次のログインで IdP の値に上書きされる**（写しは IdP を正とする。ADR-0077 §6）。
- なりすまし対策として確認メールを要するプロジェクトは、`PUT /api/auth/me` のメール変更部分をトークン確認方式へ差し替える。

### §4

- 画面の採番は S7 が `/profile/security`（`frontend/README.md` の画面遷移図・画面一覧・画面仕様・操作マニュアル）。
- どの画面にどの区画を置くかは画面側だけを見れば分かる。API は変えていない。
- 他の決定で本人の設定が増えるときも、このどちらかの区画として足す（例: 連携の区画は `/profile/security`。ADR-0077 §5）。

### §5

- サーバーへ問い合わせる新しいボタンは `ActionButton` で書く。

### §6

- **一覧の画面に追加フォームを直接置かない。** `FormDialog` は**開いているあいだだけ描画する**（`{open && <FormDialog …>}`）。
  閉じた `<dialog>` を DOM に残すと、中の入力欄が読み上げとテストの検索で一覧側の同名の項目と二重に見つかる。
- **引き金・見出し・決定のボタンで言い方を揃える。** 「ユーザーを追加」を押すと見出しが「ユーザーを追加」のシートが開き、決定は「追加」。
- jsdom は `<dialog>` の開閉メソッドを実装していない。`vitest.setup.ts` が `open` 属性の付け外しだけを肩代わりする。
  フォーカスの閉じ込め・Esc・top layer はテストで検証しない（見られるのは `data-open` と `aria-expanded` の遷移まで）。
- **新しく対応表を置くときは `<table className="matrix">` にし、行の見出しを `<th scope="row">`、値そのものの列見出しを
  `<th className="vertical">` にする。** ⚠ 縦組みの見出しの高さは 10.5rem 固定（いちばん長い scope の `admin:system-settings` が入る長さ）。
  長い名前を足すと**黙って末尾が切れる**。
- 画面の左右の余白は `--gutter` にまとめ、`env(safe-area-inset-*)` と併せて使う（`index.html` に `viewport-fit=cover`）。
  高さは `100dvh` にし、アドレスバーの伸縮でフッターが画面外へ出ないようにする。
- 一覧の中の `<code>`（`requestId`・イベント名）は狭い画面で折り返さない。読むには横になぞる。

### §7

- 実装は `frontend/src/services/appUpdate.ts`（見張り）と `frontend/src/components/AppUpdatePrompt.tsx`（知らせ）に分ける。
  部品は見張り方を引数で受け取る（Service Worker を登録する副作用を持たないので、試験で偽の見張りを渡せる）。
- 文言は `update.available` / `update.reload`（`en.json` / `ja.json`）。
- ⚠ **サーバー側の `Cache-Control` とセット**（決定 5）。`index.html` と `sw.js` に `no-cache` が付いていないと、新しい版に気付けない。
- ⚠ **知らせが出るまでの遅れは最大 30 分**（＋タブを手前に戻したとき）。互換性の無い API の入れ替えなど、即時に伝えたい変更はこれに頼らない。
- 実ブラウザでの通し確認（知らせが出て、押したら新しくなる）は `frontend/e2e/` の煙試験が受け持つ（ADR-0072 §6）。
  Vitest は「いつ確認しに行くか」「押したときに何をするか」までを見る。

### §8

- 派生アプリにも同じ直しを入れる（画面の形は派生ごとに違うので、各リポジトリの形に合わせて当てる）。
- サーバーが長く落ちたままなら、画面は「つながりません」を出し続ける（ログイン画面へは送らない）。

### §9

- 派生アプリで像を足す場所が増えても、絵を書き起こさず `AppMark` を使う。
- 画面の像だけを違う絵にすることはできない（したいなら別の決定として ADR を書く）。

### §10

- この雛形から作ったアプリへ配るのは別の課題（各アプリへ 1 本ずつ。#653）。
- ⚠ 新しい API の入口を `api.ts` を通さずに作ると、503 を受けても切り替わらない。
- 前段が自前の 503 の形を変えたら `outageFrom` を合わせる。アプリが自分で `{"error":"service_unavailable","reason":"maintenance"}` を
  最上位に返すと、同じ画面になる。
- 実ブラウザの試験（`frontend/e2e/maintenance.spec.ts`）は、edge の代わりに API へ同じ形の 503 を返す。その応答は見張り
  （`e2e/fixtures.ts`）が 5xx として数えないよう印を付ける。
