# ADR-0092: パスワードで入る人に二要素認証を必須にする設定を、アプリ全体に 1 つ持つ

- 日付: 2026-10-31
- 状態: 承認

## 文脈

IdP 側の多要素は SSO にしか効かず（ADR-0076 §3）、ローカルの二要素認証は利用者の任意だった。必須にできる設定を足す。
単位の候補はアプリ全体・テナントごと・ロールごとの 3 つ（task #794）。必須にしたことで誰も入れなくなる経路を作らない。

## 決定

1. **単位はアプリ全体。** システム設定 `LOCAL_TWO_FACTOR_REQUIRED`（既定は無効）を 1 つ持つ。ローカルの入口が閉じていれば（`LOCAL_LOGIN_ENABLED=false`）効かない。
2. **求める相手はパスワードで入ったログインだけ。** SSO は IdP に任せる（ADR-0076 §3 決定 1）。パスキーは端末の持ち物と本人確認でそれだけで二要素を満たす（ADR-0076 §2）ので、印 `passkey` をトークンに載せて引き継ぐ。機械の口は対象外。パスキーを持っていても、パスワードで入ったなら TOTP を求める。
3. **未登録のログインもログインは成立させる。** トークンに印 `two_factor_setup` を載せ、権限（scope）を空にする。通す口は本人の情報（`GET /api/auth/me`）と二要素の登録（`/api/account/security/two-factor` の取得・開始・確定）だけで、ほかは 403 `two_factor_setup_required`。更新とログアウトは主体を見ないので通る。
4. **登録待ちかはトークンを出すたびに決め直す。** 更新の口も通るので、設定を入れれば 5 分以内に今のログインへ効き、登録して更新すれば権限が戻る。印を持ち回らない。
5. **必須の間は本人が二要素を外せない**（403 `two_factor_required`）。
6. **締め出しの戻り道は 2 つ。** 必須をやめるのは画面か `scripts/unset_setting.py`（ADR-0074 §1）。端末を失くした人を戻すのは `totp_secrets` の行を消すことで、次のログインで登録し直す（画面の口は足さない。管理者が他人の入り口を消せると、管理者の乗っ取りが二要素を越える）。手順は `docs/OPERATIONS.md`。

## 理由

- **アプリ全体**: 必須にするかは運用者の方針で、1 つの値なら画面に出す説明も、戻し方も 1 通りで済む。テナントの外の人（`system-admin`）も同じ設定で守れる。

| 採らなかった案 | 捨てた理由 |
|---|---|
| ロールごと | ロールの付け外しでログインの条件が変わり、アクティブロール（ADR-0078 §1）でどのロールを数えるかも決めなければならない。絞ったロールで入れば避けられる形にもなりやすい |
| テナントごと（コンテンツ設定） | テナントに属さない運用者を守れず、別の値が要る。テナント管理者が外せると運用者の方針にならない。要るアプリは後から足せる（全体の設定を下限にできる） |
| ログインの応答で断って、別の札で登録させる | 登録の口の認証を 2 通り持つことになる。今のトークンに印を載せれば、Cookie・CSRF・更新・ログアウトをそのまま使える |
| 印を更新でも引き継ぐ | 登録の確定の口でトークンを出し直す必要があり、設定を切ったあとも印が残る |
| パスキーを持つ人にはパスワードだけで通す | パスワードが漏れれば 1 要素で入れる |

## 影響

- 登録の途中で端末の時計がずれているなどで確定できない人は、画面の「サインアウト」で抜けられる。入れないだけで、データは失わない。
- 最後の管理者が端末を失くしても、DB に入れる運用者が決定 6 で戻せる。画面だけでは戻せない。
- 有効にすると、未登録の管理者も次の更新で登録の画面になる（登録すれば戻る）。
- ⚠ 派生アプリが主体を自前で検証する口を足すときは、`refuse_during_two_factor_setup` を通す。`get_operation_principal` を直に使う口は scope が空で止まるが、scope を見ない口は止まらない。
