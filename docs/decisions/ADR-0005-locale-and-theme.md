# ADR-0005: 言語・テーマは「既定値はサーバー、選択はブラウザ」で持つ

- 日付: 2026-07-29
- 状態: 承認

## 文脈

日英の切り替えとテーマ（ライト／ダーク）切り替えを入れるにあたり、選択した値を
どこに持つかを決める必要があった。参照元の photonest はサーバー側 gettext と
`LocaleMiddleware` で訳出しているが、本テンプレートは「翻訳はフロントエンド、
API はエラーコードを返す」という方針（CLAUDE.md「国際化」）を採っている。

`LANGUAGES` / `DEFAULT_LOCALE` は設定として定義済みだったが、参照するコードが
無く、管理画面に並ぶだけで何も動かさない状態だった。

## 決定

- 表示文言の翻訳はフロントエンドの JSON 辞書のまま。サーバー側 gettext は入れない。
- 既定値と選択肢（`LANGUAGES` / `DEFAULT_LOCALE` / `DEFAULT_THEME`）は
  公開エンドポイント `GET /api/ui/settings` で配る。
- 利用者の選択は `localStorage` に保存する。優先順位は
  「利用者の選択 > ブラウザの言語（言語のみ）> サーバーの既定値」。
- テーマは `light` / `dark` / `system` の 3 値。`system` は OS の設定に追従する。
  配色は CSS 変数で持ち、`<html data-theme>` で切り替える。

## 理由

- **サーバー側 gettext を入れない**: `.po` を編集するたびに `.mo` の再生成が要り、
  訳が 2 か所（サーバーとフロント）に分かれる。API がエラーコードだけを返す設計
  なら、訳出はフロント 1 か所で済む。
- **既定値だけサーバーから配る**: ログイン前の画面でも必要なため認証は要求しない。
  これで `LANGUAGES` / `DEFAULT_LOCALE` が実際に効くようになり、「画面に並ぶが
  何も動かさない設定」が無くなる。
- **選択をサーバーに保存しない**: ユーザー毎の表示設定テーブルを足すほどの価値が
  無い。端末ごとに違ってよい種類の設定でもある（職場の端末だけダーク等）。
- **`system` を持つ**: OS のダークモードに追随しないと、夜間に画面だけ白く光る。
  `matchMedia` の変化も購読し、OS 側の切り替えに即応する。
- **配色を CSS 変数にする**: テーマの追加が `:root[data-theme=...]` 1 ブロックで
  済む。以前使っていた `Canvas` / `CanvasText`（システムカラー）はブラウザ任せで、
  アプリ側からライト／ダークを指定できなかった。

## 影響

- 管理画面で `DEFAULT_LOCALE` / `DEFAULT_THEME` を変えても、既に選択済みの利用者
  の画面は変わらない（`localStorage` が優先）。新規の利用者にだけ効く。
- 描画前に `/api/ui/settings` を 1 回取得する。失敗しても既定値で描画を続ける。
- 管理画面の設定ラベルはサーバーが英語で返す。フロントは `config.field.<KEY>` を
  辞書から引き、無ければサーバーのラベルをそのまま表示する。
