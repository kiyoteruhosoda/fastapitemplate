# ADR-0064: サインインはテナントの入口から始め、連携先はテナントの行が持つ

- 日付: 2026-10-22
- 状態: 承認

## 文脈

ADR-0061 決定 8 は「サインインはテナントを選んでから。入口の URL に `slug` を持たせ
（`/t/<slug>/login`）、そのテナントの発行者とクライアントで assay へ送る。テナントが 1 つだけの
環境では今の入口がそのまま使える」と決めた。実装するにあたって決めることが残っている。

- 連携先の設定はアプリ全体に 1 組（`OIDC_ISSUER` / `OIDC_CLIENT_ID`）で、テナントの行
  （`tenants.issuer` / `client_id`）と二重になる
- IdP から戻ってくる口（`/callback`）・停止の通知・アプリのトークンは、どのテナントの連携先で
  受けるのか
- パスワードの入口はメールアドレスで人を引く。`users.email` はアプリ全体で一意だが、assay の
  別々のテナントに同じ人が居れば、このアプリでも 2 つのテナントに同じメールアドレスの人が要る
- システム管理者（テナントに属さない）はどこから入るのか

## 決定

1. **連携先の発行者とクライアント ID はテナントの行が正本。** アプリ全体の設定に残すのは
   テナントをまたいで同じもの（クライアントの鍵・戻り先・要求する強度・名乗り方）だけ。
   `OIDC_ISSUER` / `OIDC_CLIENT_ID` は既定のテナントを作るときの初期値（移行 0015）。
2. **どのテナントの連携先を使うかは、経路ごとに 1 通りに決める。**
   - 入口（`/login`・`/provider`・`/logout`）: `?tenant=<slug>`。無ければ、テナントが 1 つだけの
     環境ではそれ、2 つ以上なら無し（SSO のボタンを出さない）
   - 戻り（`/callback`）: 送り出したときに往復状態（署名付き Cookie）へ書いた発行者。⚠ URL から
     決め直さない。往復状態の発行者と受ける連携先が違えば断る
   - 連携（ADR-0040）: 入っている利用者のテナント
   - 停止の通知・アプリのトークン: トークンの `iss`。署名を確かめる前に読むが、使うのは鍵を
     選ぶことだけで、登録の無い発行者なら連携先が無く断る
3. **メールアドレスの一意は同じ席の中だけ**（同じテナントの中、テナントに属さない人の中）。
   DB の一意制約は外し（移行 0017）、作る・変える口でアプリが確かめる
   （`shared/infrastructure/sign_in_directory.py`）。
4. **パスワードの入口の決め方**: `/t/<slug>/login` はそのテナントの中で探す。名前の無い
   `/login` は、まずテナントに属さない人、居なければテナントが 1 つだけのときのそのテナント。
   パスワードの再設定の申し込みも同じ決め方をする。
5. 画面は入った入口を覚えておき（端末の `localStorage`）、サインアウトや期限切れのあとは
   そこへ戻す。権限には関わらない。

## 理由

- **テナントの行を正本にする**: assay のクライアントはテナントごとに登録するので、クライアント
  ID はテナントの数だけある。全体の設定に 1 組持つと、どれが正しいかが 2 か所に分かれる。
- **戻りで URL から決め直さない**: 決め直せると、あるテナントで始めた往復を別のテナントの
  クライアントで完了させる形を作れる。往復状態は署名付きで書き換えられない。
- **一意を席の中に狭める**: 全体で一意のままだと、2 つ目のテナントで初めて入った人を作れない
  （SSO の自動作成が一意制約に当たって落ちる）。テナント管理者が「その人は別のテナントに居る」
  ことを 409 で知れてしまうのも避けたい。
- **名前の無い入口はテナントに属さない人を先に探す**: システム管理者はテナントを持たないので
  `/t/<slug>/login` から入れない。テナントが 1 つだけの環境で今の入口を変えないことと両立する。

## 影響

- テナントが 2 つ以上になったら、テナントの利用者に入口の URL（`/t/<slug>/login`）を知らせる。
- 定期照合（ADR-0043）は `OIDC_ISSUER` のテナントだけを照合する。照合に使うサービスアカウント
  （`MACHINE_CLIENT_ID`）は assay のテナントごとに要るので、1 つの設定では 1 テナントしか聞けない。
  ほかのテナントの停止は、停止の通知（ADR-0036）で届く。
- アプリのトークン（ADR-0045）で受けるクライアントは `APP_CLIENT_IDS` の一覧（テナントをまたいで
  1 つの一覧）。
- ログイン試行の回数制限（ADR-0058）の宛名はメールアドレスのままなので、同じメールアドレスの
  人は、テナントが違っても数えられ方を共有する。
