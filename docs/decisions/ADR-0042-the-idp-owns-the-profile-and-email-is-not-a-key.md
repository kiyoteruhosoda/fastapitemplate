# ADR-0042: 写しは IdP を正とする。メールアドレスは鍵ではない

- 日付: 2026-09-15
- 状態: 承認

## 文脈

idp の ADR-0049 が挙げたギャップのうち、3 つが同じ勘違いから来ていた
——**メールアドレスを鍵として扱っていた**こと、**IdP から配られるものを多く見積もって
いた**こと。

- **G4** プロフィールの写しが**初回以降まったく更新されない**。`provision` した一度
  だけ書かれ、assay で改名・メール変更をしても RP の表示は永久に古いまま。
- **G5** `email` が空なら `SsoEmailMissingError` で落ちる。⚠ **鍵ではないのに必須に
  していた。**
- **G7** `groups` クレームからロールを引く仕組みがあるのに、⚠ **assay は `groups` を
  発行しない** ——設定として存在するのに一度も効かない。

## 決定

### 1. 写しはログインのたびに上書きする（G4）

`FederatedUserDirectory.refresh_profile` を足し、既に結び付いている相手のログインで
毎回呼ぶ。⚠ **IdP を正とする**（ADR-0049 I5）。

⚠ **ぶつかる値は書かない。** `users.email` も `users.username` も一意なので、別の
利用者が持っている値をそのまま書くと**ログインが 500 で落ちる**。写しの更新で
ログインを壊すのは本末転倒なので、**その項目だけ見送って記録に残す**（値は残さない）。

⚠ **画面の編集はまだ残っている。** `PUT /api/auth/me` で自分の名前とメールを直せる
ので、**IdP で入る利用者がそこを直しても、次のログインで上書きされる**。
ADR-0049 の I5 は「RP では編集させない」まで求めているが、それは別の変更にする
（`docs/Progress.md`）。

### 2. メールアドレスは、要るところでだけ要る（G5）

`ClaimsMapping.apply` は `email` が無くても通す。`FederatedUser.email` は
`str | None` になった。

⚠ **断るのは「無いと決められない場面」だけ** ——初回にメールで寄せるときと、
利用者を作るとき（`users.email` は必須なので作れない）。**既に結び付いている相手は
`sub` で引けるので、メールが無くても入れる。**

表示名が取れないときは `sub` を使う。読みにくい値になるが、**表示名が空の利用者を
作るよりはよい**（後から画面で直せる）。

### 3. グループからロールは引かない（G7）

`RoleAssignment` から `group_to_roles` を落とし、`OIDC_GROUPS_CLAIM` と
`OIDC_ROLE_MAPPING` の設定も消した。残るのは `OIDC_DEFAULT_ROLES` と
`OIDC_ROLE_SYNC`。

⚠ **ADR-0049 の I6 は「権限は RP が持つ。IdP は配らない」と決めている。** assay が
`groups` を発行しない以上、引く側を残すのは「いつか効くかもしれない設定」を置いて
おくことでしかない。**効かない設定は、効くと思って触られる。**

⚠ **`OIDC_ROLE_SYNC` の意味が狭くなった。** 引き直すのは**既定のロールだけ**なので、
真にすると**管理画面で足したロールが毎回のログインで消える**。管理画面で運用するなら
偽のままにすること（既定は偽）。

## 理由

**鍵は `(iss, sub)` である**（ADR-0049 I2）。そう決めたなら、メールアドレスは
**手掛かり**であって前提条件ではない。前提条件にしていたから、出さない IdP と
つなげなくなっていた。

写しも同じ筋である。**正本が IdP にあると決めた項目は、IdP から来るたびに書き直す。**
書き直さないなら、それは写しではなく「初回にコピーしただけの別の値」になる。

### 検討して捨てた案

- **`groups` を assay 側で発行する。** I6（権限は RP が持つ）と正面からぶつかる。
  IdP が配る側に回ると、RP が増えるたびに IdP の設定が増える。
- **写しの更新でぶつかったら、ログインを断る。** ⚠ **向こうの都合でこちらが入れなく
  なる。** 直せるのは IdP 側の管理者だけなので、利用者にできることが無い。
- **`users.email` を NULL 許容にして、メール無しでも作れるようにする。** 影響が
  広すぎる（一意制約・通知・パスワードリセット）。**作れないことは断る理由として
  十分はっきりしている。**

## 影響

- **`FederatedUser.email` が `str | None` になった。** `groups` は消えた。
- **設定が 2 つ減った** —— `OIDC_GROUPS_CLAIM` / `OIDC_ROLE_MAPPING`。
  ⚠ **消えた設定を使っている配り先があれば、値は黙って無視される**（効いていなかった
  ので、振る舞いは変わらない）。
- **`FederatedUserDirectory` に `refresh_profile` が増えた**（実装は 1 つ）。
- ⚠ **IdP で入る利用者が画面で名前を直しても、次のログインで上書きされる。**
  I5 の「編集させない」は `docs/Progress.md` へ。
