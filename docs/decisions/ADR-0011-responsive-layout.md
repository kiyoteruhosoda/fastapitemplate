# ADR-0011: スマートフォン対応は CSS のブレークポイント 1 つとドロワーで行う

- 日付: 2026-07-30
- 状態: 承認

## 文脈

`frontend/src/index.css` にはメディアクエリが 1 つも無く、画面は固定幅前提の
レイアウトだった。390px 幅（iPhone 12 相当）で開くと次の状態になる。

- サイドバー（`min-width: 12rem`）が常に本文の左を占め、本文に 10rem 程度しか残らない。
- 表（`table { width: 100% }`）が列を潰しきれず**ページ全体が横スクロール**する。
- ヘッダーの言語・テーマの選択とユーザー名・ログアウトが 3 段に折り返す。
- ボタン・入力欄の高さが 2rem 程度で、指で押すには小さい。入力欄の文字が 16px 未満のため
  iOS Safari はフォーカス時に画面を自動拡大する。

対応の方針として、(a) CSS だけで組む、(b) JavaScript で画面幅を判定して別の
コンポーネントを描く、(c) UI ライブラリ（MUI 等）を導入する、の 3 つがあった。

## 決定

**CSS のメディアクエリ 1 つ（`max-width: 48rem` = 768px）で切り替える。**
狭い画面ではサイドバーを画面外へ退避させ、ヘッダーのボタン（☰）で開閉する
ドロワーにする。開閉状態は `components/AppLayout.tsx` が持ち、`nav[data-open]`
属性として CSS へ渡す。**コンポーネントは画面幅を判定しない。**

言語・テーマの選択（`PreferenceControls`）はヘッダーとドロワーの両方に置き、
どちらを見せるかは CSS（`.header-preferences` / `.sidebar-preferences`）で決める。
表は `<div className="table-scroll">` で包み、**表だけ**が横スクロールする。

## 理由

- **判定の出所を 1 か所にする。** 幅の判定を JS 側（`matchMedia`）に持たせると、
  CSS のブレークポイントと JS の閾値が二重管理になり、片方だけ直して食い違う。
  「開いているか」だけを状態として持てば、幅の解釈は CSS に閉じる。
  jsdom はメディアクエリを適用しないため、テストで検証できるのも
  `data-open` と `aria-expanded` の遷移だけになる（`AppLayout.test.tsx`）。
- **ブレークポイントを 1 つに絞る。** このテンプレートの画面は「サイドバー + カード +
  表」の 1 パターンしかない。段階を増やすほど、画面を追加する人が確認すべき幅が増える。
- **ドロワーを選んだ理由。** 項目数が最大 7 でスコープにより増減するため、横並びの
  タブやボトムナビゲーションでは収まらない（scope の有無で幅が変わる）。
  サイドバーの `ITEMS` をそのまま流用でき、ナビゲーションの定義が 1 か所に残る。
- **表は横スクロールに任せる。** 列を落とす・カード表示に変える案もあるが、どの列を
  落とすかは画面ごとの判断になり、表を足すたびに決めごとが増える。
  `min-width: 34rem` を下限に横スクロールさせれば、どの表でも同じ扱いで済む。
- 捨てた代替案:
  - **UI ライブラリの導入（MUI 等）** — スケルトンの CSS は 274 行で、
    テンプレートとして「好みの UI ライブラリへ置き換える」前提で書かれている。
    ここで特定のライブラリを入れると、その置き換えの自由を先に奪う。
  - **JS で幅を判定して別コンポーネントを描く** — 上記のとおり二重管理になる。
    加えて初回描画で幅が確定せず、レイアウトが一瞬ちらつく。
  - **言語・テーマをヘッダーに残したまま折り返す** — 390px 幅でヘッダーが 3 段
    （約 165px）になり、本文が画面の 2 割を失う。
  - **ドロワーをヘッダーの下から開く** — ヘッダーの高さは折り返しで変わるため、
    ドロワーの `top` を CSS で固定できない。ヘッダーごと覆い、閉じるボタンを
    ドロワー内に置く方が高さに依存しない。

## 影響

- **表を新しく置くときは `.table-scroll` で包む必要がある。** 忘れると狭い画面で
  ページ全体が横スクロールする。画面追加の手順（`frontend/README.md`）に明記した。
- ドロワーは開いているあいだヘッダーを覆う。閉じる手段は ✕ ボタン・オーバーレイの
  タップ・Esc・項目の選択の 4 つで、いずれも `AppLayout.test.tsx` で検証する。
  オーバーレイは装飾のため `aria-hidden` とし、支援技術からは ✕ と Esc で閉じる。
- 言語・テーマの選択が DOM 上に 2 つ存在する（片方は `display: none`）。
  操作対象を探すテストでは、どちらの `select` を指しているかに注意が必要。
- 狭い画面では入力欄・ボタンの最小高さを 2.75rem、文字を 16px にする。
  チェックボックスは枠を広げても押しやすくならないため対象から外し、
  目盛りそのものを 1.5rem にしている。
