# ADR-0008: WEB 公開ポートの既定値を build-remote-container.env から渡す

- 日付: 2026-07-30
- 状態: 承認

## 文脈

デプロイ先の WEB 公開ポート（`WEB_HOST_PORT`）は、これまで次の 2 か所でしか決められなかった。

1. `deploy.sh` が環境ディレクトリ名から決める既定値（stg=8081 / prod=8080）
2. デプロイ先の `.env`（初回デプロイで生成された後、手で書き換える）

同一ホストに複数環境を並べる、既に別サービスが 8080 を使っている、といった環境では
既定値がそのまま使えない。だが `.env` は秘密情報を含むため `dist/` にも Git にも入っておらず、
`deploy.sh` は既存の `.env` を意図的に一切書き換えない。結果として「初回デプロイを既定ポートで
一度失敗させ、生成された `.env` を手で直して再実行する」手順になっていた。

一方でデプロイ先には、環境ごとの手置き設定ファイル `build-remote-container.env` が既にある
（`APP_DEV_CONTAINER` や `APP_DIST_DIR` などビルド経路の設定。環境ディレクトリごとに 1 つ）。
ここに公開ポートの既定値も書けるようにすれば、初回デプロイから正しいポートで上げられる。

## 決定

`build-remote-container.env` に `APP_WEB_HOST_PORT` を追加し、`build-remote-container.sh` が
DEPLOY ステップで `deploy.sh` へ環境変数として引き継ぐ。`deploy.sh` はこれを
**環境ディレクトリ名由来の既定値の代わり**として使い、`.env` を新規生成するときに
`WEB_HOST_PORT` へ転記する。`.env` に `WEB_HOST_PORT` があればそちらが常に優先される。

優先順位: `.env` の `WEB_HOST_PORT` ＞ `APP_WEB_HOST_PORT` ＞ 環境ディレクトリ名由来の既定値。

## 理由

- **`.env` を正本のまま残せる。** 既存の `.env` を書き換えない `deploy.sh` の原則
  （秘密情報の保全）を崩さずに、初回生成時の既定値だけを外から与えられる。
  「毎回上書きする」設計にすると、デプロイ先で調整したポートが次回デプロイで巻き戻る。
- **設定の置き場所を増やさない。** `build-remote-container.env` は既に環境ごとの手置き設定として
  存在し、`.env` と違って「デプロイ経路の設定」を書く場所として役割が分かれている。
- 捨てた代替案:
  - **`.env.example` の既定値を変える** — 全環境に効いてしまい、環境ごとに変えられない。
  - **`deploy.sh` の引数でポートを渡す** — 手で毎回渡す値になり、`build-remote-container.sh` を
    引数なしで叩く（既定 `app`）今の運用と噛み合わない。
  - **`deploy.sh` が既存 `.env` の `WEB_HOST_PORT` 行を書き換える** — `.env` の正本性が失われ、
    デプロイ先での調整が消える。`.env` を触らない原則にも反する。
  - **`docker-compose.yml` の `${WEB_HOST_PORT:-8080}` 側で分岐** — compose はイメージに焼き込まれ
    全環境で共通なので、環境ごとの値を置く場所にできない。

## 影響

- `APP_WEB_HOST_PORT` が効くのは **`.env` が無い初回デプロイ**（`.env` 生成時）か、
  `.env` に `WEB_HOST_PORT` の行が無い場合のみ。既に `WEB_HOST_PORT` を持つ `.env` がある環境で
  ポートを変えるには、これまでどおり `.env` を直接編集する。
- あわせて `deploy.sh` が解決後の `WEB_HOST_PORT` を `export` するようにした。
  compose の公開ポートとヘルスチェック URL が必ず同じ値を見るようにするため
  （`.env` に `WEB_HOST_PORT` の行が無い環境では、従来 compose 側の既定値 8080 だけが効き、
  stg のヘルスチェック（8081）とずれていた）。
- 値の検証（1〜65535 の整数）は `build-remote-container.sh`（ビルド前）と `deploy.sh`（単体実行時）の
  両方で行う。先頭 0 付きの値は 8 進数と解釈されないよう明示的に弾く。
