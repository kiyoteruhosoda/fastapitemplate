# ADR-0060: パスキーの追加・削除とメールの変更は、入り直したばかりのときだけ

- 日付: 2026-10-21
- 状態: 承認

## 文脈

パスキーの登録・削除と、本人のメールアドレスの変更に、本人の再確認が無かった。盗まれたセッションで
パスキーを足すと、そのあとはパスワードも二要素も無しに入り続けられる。メールを自分のものへ替えれば、
再設定のメールでパスワードを奪える（2026-10-21 の脆弱性確認、task #577。deck の報告の低-3・低-4 と同じ）。
二要素の解除だけは今のコードを求めていて、扱いがそろっていなかった。

## 決定

持ち主の判断（2026-10-21）で、**「直近に実際にサインインしたこと」**を求める。

- トークンに `auth_time`（最後に**実際に**サインインした時刻）を載せる。入口（パスワード・パスキー・SSO・
  パスワードの変更）で今の時刻にし、**更新・ロールの切り替えでは引き継いで新しくしない**
  （`SessionCarryOver`）。`auth_time` を持たない古いトークンは「ずっと前」とみなす。
- パスキーの登録の開始・完了・削除と、メールアドレスの変更（表示名だけなら求めない）は、
  `auth_time` から `RECENT_SIGN_IN_SECONDS`（既定 600 秒）以内でなければ 403 `reauthentication_required`。
- 画面は断られたら知らせてログイン画面へ送る（行き先にいまの画面を持たせ、入り直すと戻る。ADR-0055）。

## 理由

- 「今のパスワードを入れる」形は、パスワードを持たない（SSO だけの）利用者がパスキーもメールも
  変えられなくなる（パスワードのログインを切った環境では全員）。「入り直したばかり」なら全員に効く。
- 判定はトークンの中だけで済み、DB を引かない（ADR-0041 と同じ）。
- 更新で新しくすると、盗んだ更新トークンを 1 回使うだけで「入り直したばかり」になれる。
- 採らなかった案: 二要素のコードを求める。二要素を設定していない人には効かない。

## 影響

- サインインから 10 分を過ぎてパスキーを足す・メールを替える人は、入り直しが 1 回要る。
- SSO の入り直しは IdP のセッションが残っていればそのまま通る（IdP 側に入り直しを強いるのは別の話）。
- 二要素認証の設定の開始は対象にしていない（パスワードを持つ人だけの口で、解除は今のコードを求める）。
