# ADR-0090: 通信先の URL と鍵のファイルの場所は環境変数だけで決める

- 日付: 2026-10-30
- 状態: 承認（持ち主が案を承認。task #743）

## 文脈

システム設定は DB > 環境変数 > 既定値で解決する（ADR-0074 §1）。そのため設定を書ける人は、サーバーの
通信先（`OIDC_ISSUER`・S3 の入口など）と鍵のファイルの場所を画面から任意の値にでき、秘密を載せた通信を
宅内や外へ向けられた。テナントの発行者にも検査が無く、discovery は転送を追った。

ただし ADR-0083 の宛先の確かめをそのまま掛けることはできない。正しい値がクラスタの内側を指す設定があり
（S3 の入口は `http://garage.blob-prod.svc.cluster.local:3900`）、宅内では assay の公開名が私設のアドレス
（10.10.2.11）を返すので、名前を引くと自分の IdP を断ってしまう。

## 決定

1. **通信先の URL と鍵のファイルの場所は環境変数だけで決める**（`ENV_ONLY_SETTINGS`。`OIDC_ISSUER`・
   `OIDC_PRIVATE_KEY_FILE`・`WEB_PUSH_VAPID_PRIVATE_KEY_FILE`・`FCM_SERVICE_ACCOUNT_FILE`・
   `APP_RELEASE_S3_ENDPOINT_URL`・`APP_RELEASE_S3_SECRET_ACCESS_KEY_FILE`）。ADR-0074 §1 の順序の例外で、
   DB に値が残っていても読まない。画面には見るだけで出し、保存は 400 `setting_env_only` で断る。
2. **`MAIL_SERVER` は画面に残し、形を確かめる**（`check_host_name`。全世界向けでない IP の直書きと内側にしか
   無い名前は 400 `invalid_destination`）。メールの送り先を変えるたびに配布を要らなくするため。
3. **テナントの発行者は https で、`OIDC_ISSUER` があれば同じホストだけ受け取る**（400 `invalid_issuer`）。
   テナントは assay のテナントであり（ADR-0079）、ホストは 1 つである。
4. **OIDC の discovery と JWKS は転送を追わない。** 転送の先では 1〜3 の確かめが効かない。
5. 名前は引かない（`ensure_public_host` を使わない）。

## 理由

- 検査で画面に残す案は、内側を指す正しい値を断るので成り立たない。許可リストを別の設定に置く案は、
  その設定をどこに置くかで同じ問題に戻る。環境変数なら変更は git の記録に残り、配布を通る。
- 値を画面から消さず見るだけで出すのは、調べるときに今の値が見えると助かるため。
- 残る穴: 公開の名前を内側のアドレスに向ければ、2・3 の形の確かめは通る（2 の宛先は SMTP のみ、3 は同じ
  ホストに限るので `OIDC_ISSUER` が空のときだけ）。設定を書ける人に限られるので受け入れる。

## 影響

- ⚠ 環境変数を入れずに DB の値だけで動かしていた設定は、取り込むと空に戻る。取り込む前に DB に残った
  キーの名前を確かめ、環境変数へ移す。DB に残った値は消さない（読まれないだけ）。
- 派生アプリには同じ形で写す。アプリにしかない通信先（`OCR_URL` など）は各アプリの `ENV_ONLY_SETTINGS` に足す。
