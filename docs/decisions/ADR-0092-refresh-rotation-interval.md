# ADR-0092: リフレッシュトークンは猶予に 1 回だけ振り替える

- 日付: 2026-10-31
- 状態: 承認
- 置き換える節: ADR-0091 決定 3 の「今の 1 本: 新しいトークン対を返す」

## 文脈

ADR-0091 では、今の 1 本が来るたびに振り替え、直前の 1 本だけを 30 秒受け付けた。stg の MariaDB と実ブラウザで 4 つのタブを同時に更新すると、ログインが終わった（`refresh_token.reused` が残り、2 つのタブがログイン画面へ）。

原因は振り替えの連鎖である。タブ 1 が T0 → T1 に振り替え、その Cookie を受け取ったタブ 2 が T1 → T2 に振り替える。この時点でまだ届いていないタブ 3 の T0 は「直前」から外れ、使い回しに見える。SQLite の試験は 1 本ずつ順に流れるので起きなかった（task #793）。

## 決定

1. **振り替えは猶予（`REUSE_GRACE_SECONDS`・30 秒）に 1 回だけ。** 前の振り替えから猶予が過ぎていない今の 1 本には、アクセストークンだけを返し、リフレッシュトークンの Cookie は載せない。
2. この条件は `UPDATE` の `WHERE` に足す（`rotated_at` が空か、猶予より前）。読んでから書かない（ADR-0091 決定 4）。
3. 直前の 1 本と、それ以外の扱いは ADR-0091 決定 3 のまま。

## 理由

- 猶予の中で「直前」が動かなくなるので、同時に走ったタブの古い 1 本は必ず受け付けられる。

| 採らなかった案 | 捨てた理由 |
|---|---|
| 直前の数本まで覚える | 何本あれば足りるかが決まらず、表の列が増える |
| 猶予を長くする | 連鎖は猶予の長さと関係なく起きる |
| 使い回しの検出をやめる | 盗まれたことに気付けない（ADR-0091） |
| 画面でタブの間の更新を 1 本にまとめる（Web Locks など） | 画面を通らない呼び出しや古い画面には効かない。サーバーで決めれば画面に依らない |

## 影響

- 猶予の中で盗まれた今の 1 本で得られるのは、寿命 5 分のアクセストークンだけ（新しいリフレッシュトークンは得られない）。
- 猶予を過ぎた最初の更新で振り替わるので、盗まれたトークンを使い回したときの検出は今までどおり働く。
