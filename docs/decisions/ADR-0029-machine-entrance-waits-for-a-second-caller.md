# ADR-0029: 機械の口はテンプレートに入れない。2 つ目の派生が要るまで待つ

- 日付: 2026-09-04
- 状態: 提案

## 文脈

ADR-0025 は SSO を取り込むときに「機械の口（`client_credentials` で得たトークンで
API を叩く経路）は**今回に含めない**」とした。ただし**いつなら入れるのか**を決めて
いなかったため、判断が宙に浮いたままになっている（Progress の T15）。

この間に材料が 2 つ変わった。

- **`aud` が使えるようになった。** 自前 idp（assay）の ADR-0042 で `resources` が
  入り、機械トークンに意味のある宛名を載せられるようになった。それ以前は `aud` が
  全員 `{issuer}/userinfo` 固定で、受け側は「自分宛か」を判定できず、blobshare は
  `aud` の検証を**明示的に諦めて** `client_id` の照合だけで認可している。
- **変わっていないこと。** `client_credentials` のトークンに `scope` は載らない
  （必ず空）。`sub` は利用者ではなくクライアント自身。「どのクライアントが何をして
  よいか」は**受け側で決めるしかない**。

## 決定

**入れない。判断の基準を決める。**

1. **テンプレートへ入れるのは、同じものが 2 つ以上の派生で書かれたとき。**
   SSO を取り込んだ根拠は「同じ判断が 3 回書かれ、3 回目で食い違った」ことだった
   （ADR-0025）。機械の口は**まだ nolumiawiki の 1 つだけ**である。2 つ目が現れた
   時点で、この ADR を新しい ADR で置き換えて取り込む。
2. **取り込むときは `acts_as`（機械を利用者として振る舞わせる）を採る。**
   クライアント専用の権限表は作らない。
3. **外せない検証は 4 つ。** ドメイン層に 1 か所で持ち、実装ごとに覚えさせない。
   - `sub_type == "client"`
   - `sub == client_id`
   - `aud` が、このアプリが `resources` に登録した名前と一致すること
   - 署名・発行者・期限（通常の ID トークン検証と同じ）
4. **監査には「機械 X が利用者 Y として」を残す。** 実行者を Y にするだけでは嘘になる。

## 理由

- **守るべき機械向けの API がテンプレートに 1 つも無い。** 入れても使われない入口を
  配ることになり、「とりあえず有効にしてみる」を誘う。テンプレートに載せる価値は
  「みんなが書くものを 1 回にする」ことにあり、まだ 1 回しか書かれていない。
- **基準を「2 回目」にするのは、SSO で使った物差しをそのまま当てるため。** 「要りそう
  だから」で入れ始めると、テンプレートは使われない機能で膨らむ。逆に 2 回目が現れた
  ときは、**放っておくと 3 回目で食い違う**ことが SSO で実証されている。
- **`acts_as` を採るのは、語彙を増やさないため。** このテンプレートは認可を
  すべて scope で決めている（ADR-0002）。機械が「ある利用者として振る舞う」なら、
  ロールと権限の仕組みがそのまま使え、新しい概念が 1 つも要らない。クライアント
  専用の権限表を作ると、人間用と機械用で同じモデルを二重に持つことになる。
- **`sub_type` の確認を落とすと素通しになる。** これが利用者主体のトークンと機械の
  トークンを分ける唯一の印で、見落とすと**誰かのログイン用トークンで機械の口が通る**。
  `sub == client_id` も要る —— idp は 2 つを別々の材料から組み立てているので、
  確かめないと「利用者の `sub` + 登録済みの `client_id`」を持つトークンが通る。
  **この 2 つは実装が忘れうる種類のもの**なので、ドメインの 1 か所に閉じる。
- **`aud` を主にするのは、`client_id` の照合より素性が良いから。** 宛名は発行の時点で
  認可サーバが確かめており、受け側は自分の名前と比べるだけで済む。`client_id` の
  照合は「知っている相手か」しか見ておらず、**別のアプリ向けに出したトークンでも
  通ってしまう**（blobshare が今そうなっている）。
- **監査の帰属を分けるのは ADR-0013 の続き。** 「誰が何をしたか」の記録で、機械の操作を
  利用者本人の操作として残すと、後から見て区別できない。

## 影響

- **Progress から T15 を落とす。** 着手予定が無いものを一覧に置かない運用のため
  （CLAUDE.md）。再開の条件はこの ADR が持つ。
- **派生アプリが自分で書く。** nolumiawiki の
  `bounded_contexts/identity_federation/`（`machine_client` / `exchange_machine_token` /
  `machine_router` と `OidcProviderGateway.verify_machine_token`）が参照実装になる。
  ただし**あちらは ADR-0042 より前の実装で、`aud` の確認が任意になっている** ——
  写すときは上の決定 3 に合わせて `aud` を必須にする。
- **2 つ目が現れたら、この ADR を置き換える ADR を書く。** そのとき決めるのは、
  `acts_as` の登録をどこに持つか（設定か表か）と、監査の帰属の表し方。
- ADR-0025 の「機械の口は含めない」を、条件付きの保留として引き継ぐ。
