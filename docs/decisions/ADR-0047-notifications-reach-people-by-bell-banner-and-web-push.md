# ADR-0047: お知らせは管理画面から送り、ベル・画面上部・端末への通知（Web Push）で届ける

- 日付: 2026-09-29
- 状態: 承認
- 関連: [ADR-0045](ADR-0045-the-app-signs-in-to-assay-directly.md) / [ADR-0048](ADR-0048-the-app-is-told-a-newer-version-is-out.md) /
  課題 task.nolumia.com #9（FCM は #59 に切り出し）

## 文脈

派生のアプリで「今夜止めます」「新しい機能が入りました」のような知らせを、利用者へ届ける手段が
無かった。メールは宛先を集めていないアプリもあり、画面の中で気付ける場所も無い。

課題 #9 で求められたのは次の形である。

- 管理画面で文言を書き、送信を押すと配信される
- 出す場所を選べる —— **ベル**・**画面の上部**・**アプリ通知の仕組み（端末への通知）**
- 宛先を選べる —— **全員**・**特定のグループ**・**個人**

テンプレートにはロールはあるが「グループ」は無い。

## 決定

1. **`notification` コンテキストを足す。** お知らせ 1 通は「中身（題・本文・行き先）」「出す場所
   （`bell` / `banner` / `push`、複数可）」「宛先（`all` / `group` / `user` のどれか 1 つ）」で決まる。
   送る権限は `notification:send`。
2. **送った時点の顔ぶれで配る。** 宛先を展開して `notification_deliveries` に 1 人 1 行書き、既読・閉じたかを
   そこに持つ。あとからグループに入った人には届かず、抜けた人の手元からも消えない。止められた利用者には配らない。
3. **グループを新しく持つ（`user_groups` / `user_group_members`、`group:manage`）。** 権限は持たず、「誰と誰か」を
   束ねるだけ。通知に閉じた概念にせず、ロールと同じく `shared` に置く。
4. **端末への通知は Web Push（VAPID）だけ。** 鍵は値ではなく場所（`WEB_PUSH_VAPID_PRIVATE_KEY_FILE`）で持ち、
   公開鍵は秘密鍵から導く。暗号化と署名は `pywebpush` に任せる。送るのは応答を返した後（`BackgroundTasks`、
   自分のセッションを開く）。通知サービスが 404 / 410 と答えた購読は外す。
5. **本人の口（`/api/notifications`）はアプリからも叩いてよい**（`AppOrWebPrincipalDep`）。スマホアプリも
   同じ口でベルと上部の知らせを出せる。
6. **行き先はこのアプリの中のパス（`/items`）か `http(s)://` だけ。** `javascript:` や `//host` は断る。

## 理由

- **送った時点で配る（決定 2）**: 「誰に送ったか」「何人が読んだか」を後から数えられる。読むたびに宛先を
  展開する形だと、グループを編集した時点で過去の配信の意味が変わる。行数は宛先の人数に比例するが、
  テンプレートが想定する規模（数十〜数百人）では問題にならない。
- **グループを新設（決定 3）**: ロールを宛先に流用する案もあったが、ロールは「何ができるか」で、
  「経理の人たち」のような束ね方には合わない（束ねるためにロールを増やすと権限の表が汚れる）。
  2026-09-29 に利用者が新設を選んだ。
- **Web Push だけ（決定 4）**: 外部サービスが要らず、PWA として入れた端末にもブラウザにも届く。
  Flutter アプリへの端末通知（FCM）は Firebase のプロジェクトと鍵が要るので、別の課題（#59）にした。
  それまでスマホアプリはベルと上部の知らせで受け取る。
- **`py_vapid` の `from_file` を使わない**: ファイルが無いと**黙って新しい鍵を作って書き出す**。
  配った公開鍵と違う鍵で署名し始め、すべての購読が静かに届かなくなる。ファイルは自分で読み、
  読めなければ「送れない」として記録に残す。
- **購読の `endpoint` へ直接一意制約を張らない**: 数百文字あり MariaDB の索引の長さを超えるので、
  sha256 を別の列に持ってそちらを一意にする。

## 影響

- 画面: ヘッダーにベル、本文の上に上部の知らせ、プロフィールに「この端末への通知」、管理に
  「グループ管理」（S17）と「お知らせの配信」（S18）が増える。
- 設定: `WEB_PUSH_VAPID_PRIVATE_KEY_FILE` / `WEB_PUSH_SUBJECT`。どちらかが空なら端末への通知は選べない
  （ベルと上部は動く）。鍵の作り方は `docs/OPERATIONS.md`。⚠ 鍵を替えると既存の購読はすべて届かなくなる。
- Service Worker に `public/push-sw.js` を `importScripts` で足した（生成物には手を入れない）。
- 依存に `pywebpush`（`py-vapid` / `http-ece` / `requests` / `aiohttp` が付いてくる）が増えた。
- 利用者を消すとき、グループの所属を明示的に外す（SQLite は外部キーの CASCADE を既定で効かせない）。
