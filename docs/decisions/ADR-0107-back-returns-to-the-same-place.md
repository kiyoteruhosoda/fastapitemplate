# ADR-0107: 「戻る」で戻ったら、見ていた位置へ戻す（全画面）

- 日付: 2026-11-17
- 状態: 承認

## 文脈

一覧から別の画面を開き、ブラウザの「戻る」で戻ると、いつもいちばん上から表示される。長い一覧では
見ていた場所を毎回探し直すことになる（task #1063。派生アプリ nolumiatask で持ち主が報告し、
nolumiatask ADR-0122 で一覧画面だけ先に直した）。

ブラウザは「戻る」で前の位置へ戻そうとするが、この雛形の画面はデータが届くまで本文を描かない
（「読み込み中」だけを出す）。戻した瞬間のページはヘッダーの高さしかなく、位置は先頭に切り詰め
られる。さらに SPA なので、リンクで別の画面を開いたときも位置はそのまま残り、新しい画面が途中
から（短ければ切り詰められて）出る。

## 決定

1. 外枠（`App`）で `hooks/useHistoryScroll.ts` の `useHistoryScroll()` を 1 回呼び、**全画面に効かせる**。
   画面ごとには何も書かない。
2. 窓の縦の位置を**履歴の 1 件ごと**（react-router の `location.key`）に `sessionStorage` へ控える
   （スクロールのたび）。ブラウザ自身の復元は切る（`history.scrollRestoration = 'manual'`）。
3. **戻る・進む（POP）のときは、ページが控えの位置まで届く高さになるのを待って戻す**（`ResizeObserver`）。
   待つのは最大 5 秒（過ぎたら届く所まで戻す）。待つ間に利用者が自分で動かした（ホイール・タッチ・
   キー・クリック）ら、戻すのをやめる。
4. **リンクで別の画面（パスが変わる）を開いたら先頭から**。同じ画面で絞り込みだけが変わる移動
   （クエリだけ・置き換え）と `#` へのリンクは位置を変えない。

## 理由

- **画面ごとに「描けたか」を渡させる形（nolumiatask ADR-0122 の `useHistoryScroll(ready)`）を採らない。**
  画面を足すたびに呼び忘れが起き、派生アプリの全画面へ写す手間も画面の数だけ要る。「高さが足りたら
  戻す」なら画面の作りを知らずに外枠だけで決まる。描けたかは、ページの高さが控えの位置に届いたかで
  ほぼ代えられる（届かないまま 5 秒経てば、届く所まで行く）。
- **react-router の `<ScrollRestoration>` は使えない。** データルーター（`createBrowserRouter`）専用で、
  この雛形は `<BrowserRouter>`。しかもあれも描いた直後に 1 回戻すだけで、データを後から取る画面
  では同じく先頭へ落ちる。
- **データの控え（キャッシュ）を持って即座に描く案は採らない。** 取得の仕組み全体を変えることになり、
  戻った時点で古い一覧を見せる別の問題を持ち込む。
- **URL ではなく履歴の 1 件ごと。** 同じ URL を 2 回開いても、それぞれの位置を持つ。タブを分けても
  混ざらない（`sessionStorage` はタブごと）。
- **訪れた最初の画面にも印を付ける。** ブックマークなどから開いた最初の 1 件は、react-router では
  どれも同じ `default` という名前で見分けが付かない。一覧そのものが最初の画面であることが多いので、
  その 1 件の履歴の状態（`history.state.key`）へ自前の名前を書き込む（再読み込みでも残る）。
  同じ URL へ置き換えで移動して名前を付けさせる案は、ログイン画面への転送などと取り合うので採らない。
- **位置は離れるときでなくスクロールのたびに控える。** 離れる瞬間には次の画面が描かれて位置が
  変わっていることがある。戻すのを待つ間（ページが短い間）は控えない。
- **利用者が動かしたらやめる。** 読み込みが遅いとき、既に読み始めた人を後から飛ばさない。

## 影響

- 控えは `sessionStorage` の `history-scroll:` で始まる名前に溜まる（タブを閉じれば消える）。
- 窓ではなく**自前のスクロール領域**（`overflow: auto` の箱）で一覧を流す画面には効かない。
  派生アプリでそういう画面を持つものは、その箱に合わせた手当てが要る。
- リンクで別の画面を開くと先頭から出るようになった（今までは前の画面の位置が残っていた）。
