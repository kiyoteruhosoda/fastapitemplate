# ADR-0050: サーバーに届かないことを、ログアウトとして扱わない

- 日付: 2026-10-04
- 状態: 承認
- 関連: [ADR-0026](ADR-0026-local-credentials-and-sso.md) / [ADR-0028](ADR-0028-tokens-live-in-cookies-only.md) /
  toeic ADR-0054（同じ直しを先に入れた派生）

## 文脈

リリースのあいだ、アプリは 1〜2 分ほど応答しない（edge が 503 を返す）。画面の殻は Service Worker が
持っているので開けるが、API は届かない。これまでの雛形では次の 2 つが重なり、派生アプリ（toeic）で
持ち主が「リリースするとログイン画面が出るが、SSO のリンクが無い」状態に取り残された。

1. `/api/auth/me` が失敗すると、理由を問わず未ログインとみなしてログイン画面へ送る
2. ログイン画面は入口の問い合わせ（`/api/auth/sso/provider`）に失敗すると、既定のパスワード欄を出したままにする
   （`frontend/README.md` S1 の「問い合わせが落ちただけで全員を締め出さない」）。パスワードの入口を
   閉じたアプリでは、出た欄は押しても通らず、サーバーが戻っても IdP のボタンは出ない

## 決定

- `/api/auth/me` が **4xx なら未ログイン**、**5xx・通信の失敗なら「届かない」**として分ける。届かないときは
  ログイン画面へ送らず「サーバーにつながりません（新しい版を配っている最中かもしれません）」を出し、
  5 秒ごとに聞き直す（`store/AuthContext.tsx` の `unreachable`・`RECONNECT_INTERVAL_MS`）
- ログイン画面は、入口の問い合わせが**届くまでどの入口も出さない**。届かなければ同じ文言を出し、5 秒ごとに聞き直す
- これまでの「問い合わせに失敗したらローカルの入口を出したままにする」（`frontend/README.md` S1）を置き換える

## 理由

- サーバーに届かないとき、どの入口を出しても押せば失敗する。出しておく意味が無く、出した既定の欄が
  サーバーが戻ったあとまで残るのが害だった
- 「全員が締め出される」心配は、届かない間に限れば当たらない（届けば入口は出る）
- 未ログインの答え（401）は届いたサーバーが返すもので、5xx・通信の失敗とは見分けられる

## 影響

- 派生アプリにも同じ直しを入れる（画面の形は派生ごとに違うので、各リポジトリの形に合わせて当てる）
- サーバーが長く落ちたままなら、画面は「つながりません」を出し続ける（ログイン画面へは送らない）
