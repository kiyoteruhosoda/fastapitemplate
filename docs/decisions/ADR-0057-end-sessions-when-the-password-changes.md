# ADR-0057: パスワードを変えたら、それより前に始まったログインを終わらせる

- 日付: 2026-10-21
- 状態: 承認

## 文脈

更新トークンはサーバーに控えが無く、署名と利用者の状態（有効か・IdP で止められていないか）だけで
確かめている（ADR-0028・ADR-0041）。そのため、**パスワードを変えても、それより前に出した更新トークンは
寿命（既定 14 日）いっぱい使える。** 本人の変更・再設定・管理者の付け直しのどれでも同じで、
「乗っ取られたかもしれないのでパスワードを変える」が効かなかった（2026-10-21 の脆弱性確認、task #574）。

## 決定

- `users.sessions_valid_from`（NULL 可）を足す。**この時刻より前に出したトークンでは、更新も出し直し
  （ロールの切り替え・資格情報を作り替える口の関門）もさせない。** 判定は IdP からの停止（ADR-0036）と
  同じ `_session_revoked` の 1 か所に置く。
- 本人の変更・再設定・管理者の付け直しで、`User.end_sessions()` が今の時刻を入れる。
- 本人が変えたときは、そのセッションだけ新しいトークンを出し直して続ける（ロールと入り口は引き継ぐ）。

## 理由

- 列 1 つで「それより前は全部無効」が言える。セッションごとの控え（deck の `auth_sessions`）を
  持てば 1 本ずつ終わらせられるが、表と書き込みが増え、雛形が抱えるには重い。
- `iat` は秒までしか持たないので、区切りも秒に切り捨てて比べる。切り上げると、区切った直後に同じ秒の
  中で出し直した自分のトークンまで断る。同じ秒の中で出た古いトークンは通るが、1 秒に満たない幅である。
- 採らなかった案: 署名鍵を利用者ごとに混ぜる（パスワードのハッシュを鍵に混ぜる）。検証のたびに DB を
  引くことになり、ADR-0041 の「アクセストークンの検証は DB を引かない」と相容れない。

## 影響

- 手元のアクセストークンは寿命（既定 5 分）まで通る（ADR-0041 の引き受けた緩さと同じ）。
- パスワードを変えると、本人の他の端末・タブも次の更新でサインアウトする。
- ログアウトはこれまでどおり Cookie を消すだけで、区切りは入れない（全端末のサインアウトになるため）。
- 移行は列を足すだけで、既存の行は NULL（区切り無し）。
