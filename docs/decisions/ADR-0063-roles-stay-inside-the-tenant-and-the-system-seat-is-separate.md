# ADR-0063: ロールはテナントの中に閉じ、システム管理者の席は別にする

- 日付: 2026-10-22
- 状態: 承認

## 文脈

ADR-0061 決定 4 は「アプリ全体に効く 3 つ（`admin:system-settings`・`system:manage`・`log:view`）を
`owner` から外して `system-admin` へ移し、`tenant:manage` を足す。システム管理者とテナント管理者は
兼ねない」と決めた。実装するにあたり、ADR-0061 が書いていないことが 3 つある。

- **ロールの表はアプリ全体で 1 つ**（`roles`）。テナント管理者は `role:manage` でロールの中身を
  変えられるが、`member` の中身を変えると、ほかのテナントの `member` まで変わる。
- `log:view` は `owner` のほかに `manager` と `auditor` も持っていた。
- 「兼ねない」をどこで守るか。ロールの付け外しの口は管理画面のほかに、SSO の既定ロール・
  ロールの同期（ADR-0025）もある。

## 決定

1. **雛形のロール（`master_data.ROLES`）は全テナントが共有し、テナントの管理者からは中身を
   変えられない**（変更・削除は 403 `shared_role`）。中身を変えたいテナントは自分のロールを作る。
   作ったロールは `role_tenants` で作ったテナントに結び、ほかのテナントからは見えない（404）。
2. **全体の権限は 4 つ**（`SYSTEM_PERMISSIONS` = `admin:system-settings`・`system:manage`・
   `log:view`・`tenant:manage`）。`system-admin` 以外のどのロールにも持たせない（雛形の `manager`・
   `auditor` からも `log:view` を外す。自作のロールからも移行で外す）。`system-admin` は加えて
   `audit:view` を持ち、全体の操作の記録（ADR-0062 決定 5）を読む。
3. **「兼ねない」は 2 か所で守る。**
   - 付ける口: テナントの中で選べるロールは、雛形のうちシステムのロール（`SYSTEM_ROLES`）でない
     ものと自分のロールだけ（`TenantMembers.roles`）。管理画面・SSO の既定ロール・同期のどれも
     ここを通るので、テナントの人に `system-admin` は付かない。
   - 効く口: トークンに載せる権限を座る場所で絞る（`within_the_seat`）。テナントの人には全体の
     権限が、テナントに属さない人にはシステムのロールの権限しか効かない。付け方を誤っても効かない。
4. **既存の環境の移り方**（移行 0016）: 自作のロールは既定のテナントのものにする。テナントに
   居る `system-admin` の持ち主は、ほかのロールも持っていれば `system-admin` を外し、
   `system-admin` だけなら既定のテナントから出してシステム管理者にする。

## 理由

- **雛形を共有にする**: ロールをテナントごとに複製する（テナントを作るたびに `owner` などを
  作る）案もある。しかし雛形は `master_data` が正本で、移行が権限を足すたびに全テナントの複製へ
  配る仕組みが要る。共有のまま変えさせないほうが、正本が 1 つで済む。テナントごとの差は
  自分のロールで表せる。
- **`log:view` を内側から外す**: アプリログはアプリ全体のもので、ほかのテナントの利用者の
  動き（パス・時刻・利用者のハッシュ）も入る。内側に残すと、テナントの中の人がほかの
  テナントの様子を覗ける。
- **2 か所で守る**: 付ける口だけだと、DB を直に触った・移行を誤ったときに兼ねてしまう。効く口
  だけだと、画面に「付いているのに効かないロール」が出る。

## 影響

- 雛形のロールを変える手段は、`master_data` と移行だけになる（画面からは変えられない）。
- ロール名は今もアプリ全体で一意（`roles.name`）。別のテナントが使っている名前のロールは
  作れない（409）。
- 派生アプリで全体に効く権限を足すときは `SYSTEM_PERMISSIONS` に入れる（入れないと、
  テナント管理者がその権限を配れてしまう）。
- ⚠ 雛形を取り込んだ派生アプリでは、`owner` が設定・再起動・アプリログの画面に入れなくなる。
  システム管理者を作るまで、その画面に入れる人はいない（手順は `docs/OPERATIONS.md`）。
