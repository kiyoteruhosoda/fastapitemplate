## 詳細

### T2 使われていない設定 `SECRET_KEY` を消す

既定の署名鍵のまま本番で起動しない仕組みは入った（`shared/kernel/settings/secret_guard.py`・ADR-0073 §4）。
残りは `SECRET_KEY`。設定として定義され `.env.example` にも載っているが、`settings.secret_key` を読んでいる
コードはどこにも無い（署名は `JWT_SECRET_KEY` だけ）。消すか、使うなら用途を書く。

### T5 ログアウトでトークンを失効させる・refresh を使い回させない

パスワードを変えたら、それより前に始まったログインは終わるようになった（ADR-0076 §8）。IdP 経由で始まった
セッションも、IdP からの停止で終わる（ADR-0077 §3）。残りは次の 2 つ。

- `/api/auth/logout` は Cookie を消すだけで、手元に控えたトークンはそのまま使える。
- refresh トークンのローテーションが無く、同じ refresh を何度でも使い回せる。

ADR-0076 §8 の「それより前に始まったログインを終わらせる」仕組みにログアウトを載せるか、`jti` の失効リストを
持つかを決めて入れる。方式は ADR に残す。

### T14 ローカルのログインにも多要素を強制できるようにする

ADR-0076 §7 で「ローカル口座を意図して持つ」と決めた。決めた以上、認証系が 2 つある
ことを前提にした運用がこちら側にも要る。棚卸し（入れる手段の一覧）は入ったので、
残りは**強制**である。

⚠ **IdP 側で `require_mfa` を掛けても、このアプリのローカルログインは素通しである。**
いま二要素認証は利用者が任意で有効にするもので、管理者が求める手段が無い。

- 設定（アプリ全体）か、ロールごとかを決める
- 強制したとき、まだ登録していない利用者をどう扱うか（ログイン直後に登録へ誘導する）
- ⚠ **締め出しの経路を作らない**（ADR-0076 §3 の `LOCAL_LOGIN_ENABLED` と同じ注意）

### T6 一覧 API のページング規約を決めて見本を置く

ログ検索（`bounded_contexts/audit/`）だけがページングを持ち、
`GET /api/admin/users`・`GET /api/admin/roles`・`GET /api/items` は全件を返す。
フロントエンドも全件を前提に描いている。テンプレートから作った先で必ず当たるので、
`limit` / `offset`（あるいはカーソル）と応答の形をテンプレートの規約として決め、
`example` に見本を置く。ADR で残す対象。

### T7 公開面の露出を絞る

`/metrics`（Prometheus）と `/info`（バージョン・git SHA・ブランチ・ビルド時刻・環境名）が**未認証**で、
同梱の nginx はすべてのパスを app へ素通しする。外向けに出す構成では、認証を要求するか nginx で内部ネットワークに
限定する。守りのヘッダーはアプリが付けるようになった（ADR-0073 §5）。

### T8 依存ライブラリの脆弱性検査を CI に足す

CI は整形・静的解析・型・テストの 8 ゲートを持つが、依存の脆弱性は見ていない。
`pip-audit`（あるいは `uv` の監査）と `npm audit` を足す。認証・パスキーを持つ
テンプレートなので、派生プロジェクトが古い `webauthn` / `pyjwt` を抱えたまま
増えるのは避けたい。

⚠ **版上げの PR は Renovate が既に立てている**（forge 側の設定が正本で、
リポジトリには何も置かない）。**`.github/dependabot.yml` を置かない**
——forge では GitHub の内蔵機能が動かないので、置いてもただのファイルになる。
ここで足すのは**脆弱性の検査**だけ。

### T9 期限切れ・使用済みパスワードリセットトークンを掃除する

`webauthn_challenges` は発行のたびに期限切れを消しているのに、
`password_reset_tokens` は使用済み・期限切れの行が残り続ける。ログ保持期間
（ADR-0075 §3）の定期実行に相乗りさせるのが素直。

### T10 `example` コンテキストを本当の見本へ育てる

README とルーターの docstring は「Item CRUD」と書いているが、実際にあるのは
作成と一覧だけで、更新・削除は無い（`bounded_contexts/example/application/use_cases/`
は `create_item.py` と `list_items.py` の 2 つ）。`items` テーブルにも
`created_at` / `updated_at` が無く、テンプレートが他所で守らせている時刻の規約を
見本自身が守っていない。**新機能を書く人が最初に読む場所**なので、更新・削除・
時刻・ページング・404 の返し方まで揃った見本にする（表記も実態に合わせる）。

### T15 ⚠ IdP で入る利用者に、名前とメールを画面で直させない

ADR-0077 §6 で**写しをログインのたびに上書きする**ようにした。一方で `PUT /api/auth/me`
は今までどおり自分の名前とメールを直せる。⚠ **IdP で入る利用者がそこを直すと、
次のログインで黙って戻る。**

idp の ADR-0049 は I5 として「**プロフィールの写しはログインのたびに上書きし、
RP では編集させない**」と決めている。結び付きのある利用者には、その 2 項目を
**画面から外す**（直す先は IdP である、と示す）。

- `PUT /api/auth/me` で、結び付きのある利用者の名前・メールの変更を断る
- 画面（S6 プロフィール）でも入力欄を出さず、IdP へ誘導する
- ⚠ **ローカル口座の利用者は今までどおり直せること**（この雛形はローカル口座を
  意図して持つ。ADR-0076 §7）
